## 0. 一分钟读懂

要把**这一次**（《未来再见》）跑通的全流程，固化成**可以反复用**的三件东西：

| # | 交付物 | 类型 | 一句话 |
|---|---|---|---|
| 1 | **翻填视频流水线** | **技能 Skill** | 知识的家：SOP、清单、规范、模板、参数化脚本。**主角** |
| 2 | **翻填视频工作流** | **Agent 预设 Preset** | 身份与外壳：开这个预设，技能自动在场、工具齐全、纪律写死 |
| 3 | **翻填工作台** | **插件 Plugin（Web UI）** | 眼睛与手：歌词对照、素材库、流水线清单、出片台、账本 |

**分层理由**（务必遵守，不要混层）：

- **插件 = 给 agent 新的手**（要写代码、要挂载、提供工具/UI/hook）
- **技能 = 给 agent 新的脑**（Markdown SOP，按需加载、改完即生效、省 context）
- **预设 = 决定这次会话是谁、带哪几只手、默认拿哪本手册上场**（组合配置）

## 1. 背景与目标

### 1.1 现状痛点

《未来再见》一次跑通，但**换第二首歌就跑不动**：

1. **脚本写死单首歌**：`scripts\80–87_pv_*.mjs` 里硬编码了 LRC 路径、`165.86s` 总长、17 段、段长表、参考图名单、封面 logo 坐标。
2. **流程知识散落**：SOP 在 `00_docs\05_PV制作流水线.md`，规范在记忆库，纪律在 `AGENTS.md`，每开新会话都要重新"想起来"。
3. **中间产物靠翻聊天记录才能找到**：用户明确要求过"要明确的文件位置"。
4. **重复劳动**：素材盘点、剥离 logo、字幕对齐、验收核验每次都重写一遍。

### 1.2 目标

> **给出任意一首"原曲 + 翻填词"的歌，用户开一个预设，就能沿着固定 SOP 产出【音乐成品 + PV 成片 + 封面 + 投稿文案】，产出物结构固定、进度可检阅、花费可追溯。**

具体可验收的目标：

- **G1** 新会话选「翻填视频工作流」预设 → 技能自动在场、H3 MCP 可用、工作台面板出现，**零手工准备**。
- **G2** 同一首《未来再见》在**新流程**下能**复现**本次交付（可只读回放，不重花钱）。
- **G3** 全流程任一时刻，用户在**工作台**上能看清：歌词对照、素材齐缺、走到哪一步、花了多少钱、产物在哪。
- **G4** 产出一份**人可读的进度文档**，逐阶段记录"做了什么、产物在哪、验收如何"。

### 2.2 已经踩过的坑（**必须写进技能，别再犯**）

| 坑 | 结论 |
|---|---|
| `image-01` 的 `subject_reference` 只收公网 URL | 参考图路线一律走 **H3 Ref2VA** |
| H3 单条 prompt **上限 7000 字符** | 写 prompt 时硬性控制 |
| Ref2VA 与首帧图 **互斥** | 要"参考+连续"就用**首镜 Ref2VA + 后续续拍** |
| 真超分 vs 重采样 | 提分辨率用 **Real-ESRGAN**；ACE/lanczos 只是重采样 |
| 字幕必须**在目标分辨率重烧** | 不要放大已烧录字幕 |
| 衍生物料**不能从成片取帧**（带字幕） | 从 `clips\` 取 |
| ffmpeg 路径被 ImageMagick 影子抢占 | 脚本一律用全路径 |
| `node -e` 内联脚本会被 PS 5.1 吃掉 | 一律写 `.mjs` 文件 |
| 静默失败 / 解析 ffmpeg 输出取错行 | 每条失败路径都打印；媒体参数用 ffprobe |
| 中文 prompt 过 PowerShell 会乱码 | 写进 `.txt` 用 `--prompt-file` |

### 2.3 用户已明确的要求（技能里要写成硬纪律）

- **非破坏性**：`01_input` / `02_stems` / `09_aceproject` / `music` 既有素材一律不删不改；新产物只新增。
- **版本化归档**：迭代产物进 `history\<时间戳>\` + README，新产物用 `vN` 命名，**绝不覆盖**。
- **成本纪律**：真实 API 调用前报预估、拿授权，`--max-cost` 兜底；逐笔台账。
- **质量型验收**：要"更清晰/更好听"这类需求，必须做**同帧/同段 1:1 对比**，不能只拿"参数达标"交差。
- **交付节奏**：给**绝对路径**并**停下来等检查**，不要自己往下走。
- **本地免费优先**：能用本机算力解决的，不花 API 钱。
- **AI 标识 + 原曲署名 + 非商用**：成片与文案必须带。

## 5. 交付物 1：技能「翻填视频流水线」

### 5.1 落点与生效机制（已核实）

DSH 本地技能由 `dsh-skill-filesystem` 按 rank 扫描固定根：

| rank | 根 | 说明 |
|---|---|---|
| 100 | `<项目根>\.dsh\skills` | |
| 200 | `<项目根>\.agents\skills` | **本项目用这个** |
| 300 | `customSkillDirs` | |
| 400 | `$DSH_HOME\skills` | |
| 500 | `~\.agents\skills` | 用户级全局（现有 19 个技能在此） |

- **只认一层深**：必须 `<root>\<名称>\SKILL.md`；嵌套 `**/SKILL.md` 不认。
- 根目录被 Chokidar 监视 → **装进去立刻生效，无需重启**。
- 本工作区**无 `.git`**，故"项目根"= 工作区目录本身 → `.agents\skills` 落点正确。

**决策：技能装项目级（rank 200）**，理由：它的 SOP 与目录约定和本项目强绑定；同时把"跨歌通用"的部分（H3 规范、超分、封面）在 SKILL.md 里注明可提升到用户级。

### 5.2 `SKILL.md` 内容大纲

```markdown
---
name: 翻填视频流水线
description: 把一首歌的"原曲 + 翻填词"做成完整的翻填翻唱成品与 PV 视频。
  当用户要"做翻填/翻唱/出 MV/做 PV/接着上次继续做某首歌/重出某段视频"
  或提到 LRC 对齐、干声分离、ACE 出人声、SVC 换音色、H3 出片、分镜、
  字幕烧录、封面、投稿文案时使用。进入「翻填视频工作流」预设时自动加载。
---

# 0. 开场必做（硬纪律）
1. 读 `_进度\进度.md`；不存在就先按模板建
2. 读 `翻填项目.json`；不存在就引导用户建（本技能 §配置）
3. 用工作台/文件确认当前阶段，**从断点续做**，不要从头重来
4. 任何花钱动作前：报预估 → 拿授权 → `--max-cost` 兜底 → 记台账

# 1. 两条交付线（总览图）
音乐线：原曲 → 分离 → 扒谱/对齐 → ACE 出人声 → SVC 换音色 → 混音 → 成品
视频线：LRC 对齐 → 分镜 → 参考图 → prompt → H3 出片 → 字幕 → 合成 → 超分 → 核验
（附：哪一步产物落在哪个目录、哪一步可能花钱）

# 2. 阶段清单（每步：目标 / 命令 / 产物 / 验收 / 是否花钱）
# 3. 产出物文件结构约定（强制）
# 4. 进度文档写法（强制，见 §5.5）
# 5. 硬边界（非破坏性 / 成本 / 质量型验收 / 版本归档 / 版权标注）
# 6. 常见坑（第 2.2 节那张表）
# 7. 什么时候该并行开子代理
# 8. references 索引
```

## 7. 交付物 3：工作台（Web UI 插件）

### 7.1 设计原则

1. **异常优先，而不是平铺**——用户说"可收纳/可折叠"，更好的做法是**默认只亮出"需要你注意的"**，正常的自动收起。
2. **角色驱动，而不是文件类型驱动**——素材库按"在流水线里扮演什么角色"分组，而不是按扩展名堆列表。
3. **清单可执行，而不只是可读**——每一步都能"点一下让 agent 去跑"（能力不足时降级为复制命令）。
4. **只读优先，写回最小**——MVP 只读，避免 UI 与 Agent 打架；写回仅限配置类选项。
5. **样式只用主题 token**（技能明确要求：不得 import Harness Client 包），保证亮/暗主题都正常。

### 7.2 界面设计（自主设计版）

### 7.4 实现路径与降级

参考 `cordis-plugin-development` 技能：

1. **先探测再动手**：`cordis_inspect_list` → 针对 `Slots.listSubTree` 与 `Theme` 做定向 `cordis_inspect_query`，确认**可用插槽**与主题 token。
2. **先装再美化**：从该技能的 `templates/decoration/`（`package.json` / `cordis.patch.yml` / `index.js` / `client.js`）复制到 `dev\翻填工作台\`，**先装一个只读小版本**，用插件本身当第一版预览（不要先做 HTML 预览稿）。
3. **验证以安装结果为准**：看 `application` / `warnings` 字段，而不是服务端日志。
4. **客户端改动热更**需要同一 checkout 跑 `pnpm run dev:web`；否则**改完要刷新页面**。

**降级阶梯**（能力不足时逐级退，不要卡住）：

| 级别 | 形态 | 触发条件 |
|---|---|---|
| L1 | 只读面板（状态条 + 素材库 + 出片台 + 账本） | 默认目标 |
| L2 | L1 + 歌词对照 + 清单勾选 | 插槽与数据读取能力允许 |
| L3 | L2 + `[▶ 让 agent 跑]`（向会话发消息） | 宿主提供对应 API |
| **L0 兜底** | 纯 Markdown：`_进度\进度.md` 渲染成面板 / 用 `sidebar_open` 打开进度文档 | 任何 UI 插件都装不上时 |

> **L0 是保底的**：即使工作台一行代码都没写成，`进度.md` + 素材清单也能让用户看清全局。**先保证 L0 质量，再追求 L1/L2。**
