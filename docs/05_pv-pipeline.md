# PV 制作流水线（通用）

> **性质**：一条"原曲 + 翻填词 → PV 成片"的**通用**操作流程。文中所有具体数字都来自一次真实交付，
> 作用是**给你量级与阈值**，不是要你照抄——你的素材不同，数字就该不同。
> **视频模型**：以 MiniMax-H3（768P / 24fps / 原生音频）为参考实现，换同类模型只需改配置与驱动。
> **产物根目录**：由配置的 `video.dir` 决定（默认 `10_video/`；历史工程可显式指向别的布局）。
> 相关文档：[04_h3-workflow.md](./04_h3-workflow.md)（H3 API 与工具账本）

---

## 一、流水线八步

| 步 | 脚本 | 作用 | 是否花钱 |
|---|---|---|---|
| P0 | `scripts/80_pv_shotlist.mjs` | LRC↔人声对齐预检 + 分镜切分 + 成本估算 + prompt 骨架 | 否 |
| P0 | `scripts/80b_check_prompts.mjs` | 提示词合规检查（三段式/六段式/对齐指令/时间码/收尾拍） | 否 |
| P1 | `scripts/81_pv_refs.mjs` | 把 CG 原图处理成**干净参考图**（ffmpeg `delogo` 擦水印 + 缩放） | 否 |
| P2/P3 | `scripts/82_pv_clips.mjs` | 批量出片（波次并行、链式衔接、逐段 ffprobe 核验、逐次记账） | **是** |
| P4 | `scripts/83_pv_subs.mjs` | LRC → ASS/SRT + 片头信息卡 + 片尾署名（行级、跟随实测收声） | 否 |
| P4 | `scripts/84_pv_assemble.mjs` | 归一化 → 拼接 → 烧字幕 → 混母版音频 → 成片 | 否 |
| P5 | `scripts/85_pv_verify.mjs` | 七项验收核验（规格/响度/指定画面/字幕/原创性/接缝） | 否 |
| P5 | `scripts/86_pv_cover.mjs` / `87_pv_upscale.mjs` | 封面；本地真超分（Real-ESRGAN） | 否 |

一键顺序：`80 → 80b → 81 → 82 → 83 → 84 → 85`（`86` / `87` 按需）。

每一步都支持 `--plan`：只打印"将要做什么 + 预估花费"，**不发请求、不写产物**。

## 二、关键决策：为什么放弃"先出关键帧"的路线

**原计划**：先用图像模型的 `subject_reference` 把 CG 二创成新关键帧，再用视频模型做首帧图生视频（I2VA）。

**实测结论**（四种取值形态全部被拒，有据可查）：

| 试过的取值形态 | 服务端返回 |
|---|---|
| `subject_reference: "<dataURL>"`（字符串） | `status_code=2013 invalid params` |
| `subject_reference: {type:'character', image:<dataURL>}`（裸对象） | `invalid params` |
| `subject_reference: [{type:'character', image:<dataURL>}]`（数组，**形态正确**） | `status_code=1000 disallowed image url: localhost or private address not allowed` |
| 同上，`image` 换成 `mm_file://<file_id>` / 裸 `file_id` | 同样 `1000 disallowed image url` |

→ **`subject_reference[].image` 只接受公网可访问的 http(s) URL**。没有图床，这条路就走不通。

> 排查心得：`aspect_ratio` 的校验发生在参考图解析**之前**，所以拿"故意传错 ratio"当判别器会得到大量
> **假阳性**——必须用合法参数真实调用才能判定。这条对任何参数化 API 都适用。

**替代方案**：改用**视频模型的原生参考图模式（Ref2VA）**——把 CG 直接作为 `reference_image` 送进去
（支持 `mm_file://`，本地文件自动上传），由模型在生成视频时完成"二创"。

| | 图像关键帧路线（废弃） | 视频原生参考路线（采用） |
|---|---|---|
| 原图用法 | 只作风格/角色参考 | 只作 `reference_image` 风格/角色参考 |
| 是否把原图画进成片 | 否 | 否（抽样最大 SSIM 0.52–0.61，远低于 0.90 红线） |
| 构图可控性 | **高**（可先定关键帧） | 低（构图由模型决定） |
| 成本 | 多一层图像费用 | 0 额外成本 |
| 首帧连续性 | 可用关键帧钉死 | 用**链式**（上一段末帧→下一段首帧）或参考图 |

**于是分镜的生成模式按"用途"分配**（而不是按段号约定）：

| 模式 | 用在哪类段 | 说明 |
|---|---|---|
| `T2VA` | 纯文本段 | 无参考图。适合片头信息卡这类"不需要具体角色"的镜头 |
| `Ref2VA` | 需要贴合特定素材的段 | 六段式 prompt + 1–2 张参考图，构图由模型决定 |
| `I2VA` | **链式续拍段** | 取上一段**实际末帧**作首帧，保证连续 |
| `FL2VA` | 首尾帧转化段 | 给首帧 + 尾帧，由模型插值出中间过程 |

> 六段式与首尾帧的详细规范见仓库技能 `h3-prompt-writing`（`references/ref-en.txt` 与 `base-en.txt`）。
> 本仓库的 `references/03_prompt规范.md` 也整理了模板与真实实例。

**最关键的一条约束**：**参考图与首帧图互斥**。既要"参考某张素材"又要"与上一段连续"，只能拆成
**首镜用 Ref2VA + 后续段用上一段末帧做 I2VA**，不能在一段里同时要。

## 三、分镜表

产物落 `<planDir>/segments.json` 与 `shotlist.csv`（脚本与工作台共享）。设计要点：

- **无缝铺满全曲**：相邻段的 `end` 与下一段 `start` 必须相等
- **逐句歌词零切断**：任何切点都不得落在一句歌词的实测发声区间内
- **合成边界全部落在实测静音谷里**（不是"名义"停顿）
- **单段 ≤ `segMaxSec`**（默认 15s）：模型限制，且段越长越容易漂
- `genDur` = 段长**向上取整**并夹在模型允许的范围内（一次真实交付里全片 165.86s → 生成 174s）

真实交付的一次实测：某个尾奏切点按计划放在 157.0s，但人声到 159.5s 才真正收声，
脚本自动把它**吸附**到 159.5s —— 这就是为什么切点必须按实测走。

## 四、对齐预检（P0 的核心价值）

用**人声干声轨**（不是全轨混音）提取 8kHz 单声道 RMS 包络（20ms/帧、±100ms 平滑），做两件事：

1. **逐句起音检测**：每句歌词在 LRC 名义时间 ±0.8s 内找最陡的能量上升点 → 得到**实测起音与偏差**
2. **静音谷判定**：合成切点必须比 ±2s 局部峰值低 ≥8dB（纯静音区直接放行）

为什么要信实测而不是 LRC：歌词文件是**手工对的艺术品，不是测量结果**。一次真实交付里 24 句中有
3 句偏差超过 0.4s，最大一句 **+0.81s**；同步率统计是"24 句中 20 句 ≤0.32s"。
别拿"大部分都对"当借口——错的那几句正好会让切点切进词里。

处置口径（`plan/lyrics_timing.csv`）：

- 偏差 ≤0.35s：用 LRC 原值（人工标注更稳）
- 偏差 >0.35s：改用实测起音，**单句最多校正 0.6s**（防止被离群点带飞）
- 字幕按**校正后**的时间轴走
- 收尾用实测收声时刻截断——否则"后面接长间奏"的那句会让字幕挂满整个间奏
  （真实案例：一句后面接约 30s 间奏，字幕被从 30.0s 收到 6.77s）

## 五、提示词规范（本流水线约定）

- 每段一个文件：`prompts/NN_slug.txt`（基线三段式）或 `prompts/ref2va/NN_slug.txt`（六段式）
- 全英文；**禁止对白**（人声来自母版）；**禁止画面出现任何文字**
  （必须显式写 `no on-screen text, no watermark, no logo`）
- `non_diegetic_music` 一律 `N/A`（配乐用母版）
- 时间轴总长 == 该段 `genDur`；必须有 `At MM:SS.mmm` 形式的**可观察时序节拍**，
  且要**收束到片尾**（`... holds until the video ends at 00:0N.000`）——
  否则模型会自行编造最后 1–2 秒
- **单条 prompt ≤ 7000 字符**（模型硬顶）。一次真实交付的实测区间是 1987–6649，余量不大，必须自检
- 风格前缀全片统一（赛璐璐厚涂、干净线稿、强对比电影光）
- **同素材跨段口径必须一致**（同一主体在多个段出现时，数量/形状/归属都要一致）——
  这是**并行撰写最容易翻车**的地方，靠"独立评审 agent 回看原图"抓出来

## 六、成本与审批门

出片是整条链路**唯一花钱**的环节，所以按"门"分批放行：

| 门 | 内容 | 量级 |
|---|---|---|
| Gate A | 分镜 + 素材分配 + 成本预估 | ¥0（纯本地预检） |
| Gate B | 关键帧定调 | （走"先出关键帧"路线时才有；该路线废弃后取消） |
| Gate C | **试片**（1–2 段，验证链路与画风） | 一二十秒的量级 |
| Gate D | 批量出片（剩余全部段） | 全片的主要开销 |
| Gate E | 全片核验 | ¥0 |

纪律：

- **一次总授权 + 逐笔台账**，不做逐步确认；只在预估会突破 `budget.totalCny` 时停
- 每条命令都要有 `--max-cost` 兜底；`--plan` 先看预估
- 逐次尝试都记账（含失败；失败计费口径要跟供应商确认清楚）
- 一次真实交付的参照量级：768P 全片名义 ¥87，加上试片与两轮重出后实际 **¥109.50**

## 七、验收标准（`85_pv_verify.mjs` 自动出报告）

1. **规格**：时长与音频一致（±0.05s）、分辨率、帧率、H.264/H.265 + AAC
2. **响度**：I = −14 ±1 LUFS、TP ≤ −1 dBTP
3. **指定画面**抽帧存盘，供人眼复核（哪些时间点是配置里 `video.mandated` 定的）
4. **字幕**：歌词句数全部出现、字体单一
5. **原创性**：每 4s 抽帧 vs 该段参考图，最大 SSIM **< 0.90**（越低越"二创"）
6. **接缝**：相邻段末帧/首帧 SSIM 表；**链式接点要求 ≥ 0.60**
   （链式接点由 `chainFrom != null` 推导，不要写死段号）
7. 报告落 `<verifyDir>/report.md`

> **判读口径很重要**：转场接点的 SSIM **高**才是好（要求趋近连续），
> 硬切接点的 SSIM **低**是**正常且期望**的——别把硬切当失败。

**但"七项全绿 ≠ 目标达成"**：如果用户要的是"更清晰/更好看"，参数合格不算交付，
必须做**同帧 1:1 对比**（见技能 `references/04_验收清单.md`）。

## 八、已知取舍与可改进项

1. **转场以硬切为主**：溶解（`xfade`）会缩短总时长，破坏与歌词的逐句对齐。
   要做溶解，必须在**生成阶段多留 0.4s 余量并重算时间轴**——不是合成阶段能补的。
2. **构图可控性**：Ref2VA 的起始构图由模型决定，不保证与原图逐像素对齐；
   某段构图不满意就**重出该段**（按秒计费），不要试图在合成阶段修。
3. **首尾帧精确控制**：因为参考图与首帧图互斥，想做 A→B 的**转化**只能用
   "双参考图 + 时序描述"或首尾帧模式，不能两者兼得。今后若有了公网图床，可以回到
   "图像出关键帧 + 首尾帧插值"的路线。
4. **交付分辨率**：基准档出片 + **本地真超分**是最省钱的组合；真要高分辨率原生出片，
   成本大致按单价比例上涨。别用重采样冒充超分。
5. **画风差距**：模型学到的是"某种动画风格的近似"，不是原画师笔触；
   配角脸部细节在快速运动镜头里可能不够稳。**这是模型能力边界，不是参数问题**——
   想改善只能从素材与提示词入手，或接受它。
