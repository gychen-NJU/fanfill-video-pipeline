## 二、关键决策：为什么最终没用 image-01 生成"二创关键帧"

**原计划**：先用 MiniMax `image-01` 的 `subject_reference` 把 CG 二创成新关键帧，再用 H3 做首帧图生视频（I2VA）。

**实测结论（2026-09-27，全部有据可查）**：

| 试过的取值形态 | 服务端返回 |
|---|---|
| `subject_reference: "<dataURL>"`（字符串） | `status_code=2013 invalid params` |
| `subject_reference: {type:'character', image:<dataURL>}`（裸对象） | `invalid params` |
| `subject_reference: [{type:'character', image:<dataURL>}]`（数组，**形态正确**） | `status_code=1000 disallowed image url: localhost or private address not allowed` |
| 同上，`image` 换成 `mm_file://<file_id>` / 裸 `file_id` | 同样 `1000 disallowed image url` |

→ **`subject_reference[].image` 只接受公网可访问的 http(s) URL**，本机没有图床，这条路走不通。
（排查心得：`aspect_ratio` 校验在参考图解析**之前**，所以用"故意传错 ratio"当判别器会得到大量**假阳性**——必须用合法参数真实调用才能判定。）

**替代方案（已采用）**：改用 **H3 原生参考图模式（Ref2VA）**——把 CG 直接作为 `reference_image` 送给 H3（H3 支持 `mm_file://`，本地文件自动上传），由 H3 在生成视频时完成"二创"。

| | image-01 关键帧路线（废弃） | H3 原生参考路线（采用） |
|---|---|---|
| 原图用法 | 只作 `subject_reference` 风格/角色参考 | 只作 `reference_image` 风格/角色参考 |
| 是否把原图画进成片 | 否 | 否（SSIM 实测 0.53–0.61，远低于 0.90 红线） |
| 构图可控性 | 高（可先定关键帧） | 低（构图由模型决定） |
| 成本 | 多一层图像费用 | 0 额外成本 |
| 首帧连续性 | 可用关键帧钉死 | 用链式（上一段末帧→下一段首帧）或参考图 |

**因此分镜的生成模式最终是**：

| 模式 | 用于 | 说明 |
|---|---|---|
| `T2VA` | 段 1/2/3（前奏） | 纯文本生成，无参考图 |
| `Ref2VA` | 段 4/5/6/7/8/9/10/11/14/15/16/17 | 六段式 prompt + 1–2 张 CG 参考图 |
| `I2VA` | 段 12/13（间奏） | 取上一段**实际末帧**作首帧，保证链式连续 |

> Ref2VA 的六段式规范：`C:\Users\13676\.agents\skills\h3-prompt-writing\references\ref-en.txt`
> T2VA / I2VA / FL2VA 规范：同目录 `base-en.txt`

## 四、对齐预检（P0 的核心价值）

用**人声轨** `翻填.Vocals.wav`（不是全轨）提取 8kHz 单声道 RMS 包络（20ms/帧、±100ms 平滑），做两件事：

1. **逐句起音检测**：每句歌词在 LRC 时间 ±0.8s 内找最陡的能量上升点 → 得到实测起音与偏差
2. **静音谷判定**：合成切点必须比 ±2s 局部峰值低 ≥8dB（纯静音区直接放行）

结果：**20/24 句偏差 ≤0.32s，没有系统性偏移**；3 句超 0.4s（最大末句 +0.81s）。
据此生成 `plan/lyrics_timing.csv`：偏差 >0.35s 的句子改用实测起音、**单句最多校正 0.6s**，字幕按校正后时间轴走。

字幕收尾还用 `vads[].sungEnd`（实测收声时刻）截断，避免「梦醒啦」这类后面接 30 秒间奏的句子把字幕挂满 30 秒（实测已从 30.0s 收到 6.77s）。

## 五、提示词规范（本项目约定）

- 每段一个文件：`prompts/NN_slug.txt`（T2VA/I2VA）或 `prompts/ref2va/NN_slug.txt`（Ref2VA）
- 全英文；**禁止对白**（人声来自母版）；**禁止画面出现任何文字**（必须写 `no on-screen text, no watermark, no logo`）
- `non_diegetic_music` 一律 `N/A`（配乐用母版）
- 时间轴总长 == 该段生成秒数；必须有 `At MM:SS.mmm` 形式的**可观察时序节拍**，且要**收束到片尾**（`...holds until the video ends at 00:0N.000`），否则模型会自行编造最后 1–2 秒
- 风格前缀全片统一（赛璐璐厚涂、干净线稿、强对比电影光）
- 同素材跨段口径必须一致（机甲数量、翼形、武器归属）——这是并行撰写最容易翻车的地方，靠**独立评审 agent 回看原图**抓出来

## 七、验收标准（`85_pv_verify.mjs` 自动出报告）

1. 时长 165.86 ±0.05s、1344×768、24fps、H.264 + AAC
2. 响度 I = −14 ±1 LUFS、TP ≤ −1 dBTP
3. 四处指定画面抽帧存盘（48s / 68s / 86s / 134s）供人眼复核
4. 24 句歌词全部出现在 ASS 中、字体单一
5. **原创性**：每 4s 抽帧 vs 该段参考图，最大 SSIM **< 0.90**
6. **接缝**：相邻段末帧/首帧 SSIM 表；链式接点（12、13）要求 ≥0.60
7. 报告落 `10_h3video/pv/verify/report.md`

## 八、已知取舍与 v2 可改进项

1. **转场以硬切为主**：计划里写过"转场点 0.4s 交叉溶解"，实作用硬切——因为 `xfade` 会缩短总时长，破坏与歌词的逐句对齐。若要做溶解，需要在生成阶段多留 0.4s 余量并重算时间轴，属于 v2 工作。
2. **构图可控性**：Ref2VA 的起始构图由模型决定，不保证与原图逐像素对齐；若某段构图不满意，重出该段即可（¥0.5/s）。
3. **首尾帧精确控制**：由于图生视频与参考图驱动**互斥**，段 5 的 A→B 转化改用"双参考图 + 时序描述"实现，而非首尾帧插值。若日后有了公网图床，可回到 image-01 + FL2VA 路线。
4. **2K 版**：当前 768P。若要 1080p 交付，对满意段做 `regenerate` 到 2K 再下采样。
5. **真人/官方画风差距**：模型学到的是"崩坏3 动画风格"的近似，不是官方画师笔触；配角脸部细节在快速运动镜头里可能不够稳。
