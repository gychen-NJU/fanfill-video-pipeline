# 翻填视频流水线（fanfill-video-pipeline）

一条把「原曲 + 翻填词」变成【音乐成品 + PV 成片 + 封面 + 投稿文案】的固定流水线。

这条线的价值不在任何单步，而在**顺序**与**边界**：音乐线的产物是视频线的输入，视频线的分镜必须踩在音乐线的实测时间上；任何一步跳序，代价都在后面成倍放大。所以先读完全文再动手。

## 0. 开工必做（硬纪律）

开工四件事，按顺序，**不要跳过**：

1. **读** `<工作区>/_进度/进度.md`。不存在就按 `references/07_进度文档写法.md` 建一个。
   这是断点续做的事实来源——**不要从头重来，不要凭记忆猜做到哪了**。
2. **读** `<工作区>/翻填项目.json`。不存在就引导用户建（规范见 `00_docs/08_翻填项目配置规范.md`）。
   它是脚本的唯一参数来源；**脚本不读它就没法跑**。
3. **看当前阶段**（进度.md 的阶段总表 + 目录实际内容），从断点续做。
4. **任何花钱动作前**：报预估 → 拿授权 → `--max-cost` 兜底 → 记台账。
   用户已明确"不要太多瓶颈"——所以是**一次总授权 + 逐笔台账**，不逐步确认；只在预估会突破 `budget.totalCny` 时停。

> 用户的交付节奏偏好：给**绝对路径** + **停下来等检查**，不要自己一路往下跑到花完钱。

## 1. 两条交付线

```
音乐线  原曲 → 分离 → 扒谱/对齐 → ACE 出人声 → (SVC 换音色) → 混音 → 成品
视频线  LRC 对齐 → 分镜 → 参考图 → prompt → H3 出片 → 字幕 → 合成 → 超分 → 核验
```

| 步骤 | 产物落点 | 花钱？ |
|---|---|---|
| 素材盘点 / LRC 校验 | `00_docs/`、`<planDir>/material_survey.md` | 否 |
| 人声分离 | `02_stems/` | 否（本地） |
| 扒谱 / 对齐版 MIDI | `03_midi/`、`01_input/*_对齐版_*BPM.mid` | 否 |
| ACE 出人声 | `05_vocals/`、`09_aceproject/`（只读保护） | 否 |
| SVC 换音色 | `06_svc/` | 否（本地 GPU） |
| 混音 + 响度 | `07_mix/`、`08_release/` | 否 |
| LRC 对齐 + 分镜 | `<planDir>/segments.json`、`lyrics_timing.csv`、`shotlist.csv` | 否 |
| 参考图去水印 | `<refDir>/` | 否 |
| **H3 出片** | `<clipDir>/`、`<planDir>/cost_log.csv` | **是** |
| 字幕 | `<subDir>/*.ass`、`*.srt` | 否 |
| 合成 | `<dir>/<歌名>_PV_v2.mp4` | 否 |
| 本地超分 | `<dir>/*_1080p.mp4` | 否（耗时） |
| 核验 | `<verifyDir>/report.md` + 抽帧 | 否 |
| 封面 | `<coverDir>/` | 否 |

**目录名不是写死的**——全部从 `翻填项目.json` 的 `video.*Dir` 读。本歌（《未来再见》）沿用旧布局 `10_h3video/pv/...`，新歌默认 `10_video/...`。

## 2. 阶段清单

每一步都是：**目标 → 命令 → 产物 → 验收**。命令里的 `<cfg>` 指工作区根。

### 阶段 1 · 素材盘点与配置

- **目标**：确认输入的"料"齐不齐，把 `翻填项目.json` 填对。
- **命令**：人工 + 视觉普查（`image_vision` 批量看图）；`ffprobe` 量分辨率与时长。
- **产物**：`<planDir>/material_survey.md`（每张素材的分辨率、内容、logo 位置、适配性）。
- **验收**：每张素材有"能不能用、怎么裁"的结论；`song.totalSec` 与 `audio.master` 实测一致（±0.05s）。
- **坑**：非 16:9 素材入画前要裁/补边；**低分辨率素材（≤1320×600）先放大再派生物**。

### 阶段 2 · 分离 / 扒谱 / 出人声 / 混音

细节见 `references/01_音乐链路.md`。要点：

- 分离两条路线（ACE Stem Splitter / python-audio-separator + BS-Roformer）都行，**产物落 `02_stems/`**。
- **先设 tempo 再导入 MIDI**；ACE 里**换声库会重置歌词**——必须重铺并回读校验。
- 混音目标 **−14 LUFS / TP ≤ −1 dBTP**，做**双 PASS** 确认。

### 阶段 3 · 歌词对齐与分镜

- **命令**：`node scripts/80_pv_shotlist.mjs`（`--plan` 只打印不写）
- **产物**：`<planDir>/segments.json`（内含逐句实测起音）、`lyrics_timing.csv`、`shotlist.csv`、`alignment_report.md`
- **验收**：无缝铺满全曲；每段 ≤ `segMaxSec`；**零切断歌词句**；合成边界落在真实静音谷。
- **必须**：用实测起音校正 LRC 名义时间；边界自动**吸附**到静音谷（本歌实测把 157s 吸到 159.5s）。
- 分镜设计规则、链式续拍、LRC 解析细节见 `references/02_PV链路.md`。

### 阶段 4 · 出片（**唯一花钱的阶段**）

- **命令**：`node scripts/82_pv_clips.mjs --only 1,2,3 --max-cost 25`
- **产物**：`<clipDir>/<idx>_<slug>.mp4`、`<planDir>/cost_log.csv`
- **验收**：逐段 `ffprobe` 量实测时长与分辨率；链式段的接点 SSIM 达标。
- **硬约束**：单条 prompt ≤ **7000 字符**；**Ref2VA 与首帧图互斥**；要"参考 + 连续"就用
  **首镜 Ref2VA + 后续用上一段末帧续拍**。
- prompt 写法见 `references/03_prompt规范.md`；成本口径见 `references/06_成本与授权.md`。

### 阶段 5 · 字幕与合成

- **命令**：`node scripts/83_pv_subs.mjs --w 1920 --h 1080 --tag 1080` → `84_pv_assemble.mjs`
- **产物**：`<subDir>/*.ass`、`<dir>/<歌名>_PV_v2.mp4`
- **硬规则**：字幕**行级**、跟随**实测收声**、保底 **3s**；多分辨率时**在目标分辨率重烧**，
  **绝不放大会烧录过的字幕**。

### 阶段 6 · 超分与核验

- **命令**：`node scripts/87_pv_upscale.mjs` → `node scripts/85_pv_verify.mjs --w 1920 --h 1080`
- **产物**：`<dir>/*_1080p.mp4`、`<verifyDir>/report.md` + 抽帧
- **硬规则**：提分辨率用 **Real-ESRGAN 真超分**，不是 lanczos/ACE 重采样（那只是放大像素）。
- 7 项核验与"质量型需求"的验收办法见 `references/04_验收清单.md`。

### 阶段 7 · 封面与投稿文案

- **命令**：`node scripts/86_pv_cover.mjs --only D`
- **产物**：`<coverDir>/封面_<版式>_<尺寸>.jpg`、`<dir>/投稿文案.md`
- 封面必须带官方 logo + AI 标识；文案必须带原曲署名。

## 3. 产物文件结构约定（强制）

见 `references/05_目录与命名.md`。三条铁律：

1. **新产物只新增**，命名冲突自动加 `-2` / `-3` 后缀。
2. **迭代替换**：旧产物移入 `<historyDir>/<时间戳>/` 并写 README，新产物用 `vN` 命名，**绝不覆盖**。
3. `01_input` / `02_stems` / `09_aceproject` / `music` 是**只读保护区**，不删不改。

## 4. 进度文档（强制）

**单一入口**：`_进度/进度.md`。每次操作批次结束**追加**，不重写历史。
模板、状态符号、台账格式见 `references/07_进度文档写法.md`。

打分：**进度.md 是项目内、给用户看的**；跨会话结论才写记忆库。不要双写负担。

## 5. 硬边界

| 边界 | 具体要求 |
|---|---|
| **非破坏性** | `01_input`/`02_stems`/`09_aceproject`/`music` 零改动；改产物先归档到 `history/` |
| **成本** | 一次总授权 + 逐笔台账；`--max-cost` 兜底；超 `budget.totalCny` 才停 |
| **质量型验收** | 要"更清晰/更好听"这类需求，必须做**同帧/同段 1:1 对比**，不能拿"参数达标"交差 |
| **交付节奏** | 给**绝对路径** + **停下等检查**，不要自己往下走 |
| **本地免费优先** | 本机算力能解决的不花 API 钱（超分、分离、混音全本地） |
| **版权标注** | 成片与文案必须带 **AI 标识 + 原曲署名 + 非商用** |
| **Windows** | 优先写 `.mjs`（规避 PS 5.1 编码坑）；**不要 `node -e` 内联**；ffmpeg 用全路径 |

## 6. 常见坑（踩过的，别再犯）

| 坑 | 结论 |
|---|---|
| `image-01` 的 `subject_reference` 只收公网 URL | 参考图路线一律走 **H3 Ref2VA** |
| H3 单条 prompt **上限 7000 字符** | 写 prompt 时硬性控制，脚本要自检 |
| **Ref2VA 与首帧图互斥** | 要"参考+连续"→ 首镜 Ref2VA + 后续用上一段末帧续拍 |
| 真超分 vs 重采样 | 提分辨率用 **Real-ESRGAN**；lanczos/ACE 只是重采样 |
| 字幕必须**在目标分辨率重烧** | 不要放大已烧录字幕 |
| 衍生物料**不能从成片取帧**（带字幕） | 从 `<clipDir>/` 取 |
| ffmpeg 路径被 ImageMagick 影子抢占 | 脚本一律用全路径 |
| `node -e` 内联脚本会被 PS 5.1 吃掉 | 一律写 `.mjs` 文件 |
| 静默失败 / 解析 ffmpeg 输出取错行 | 每条失败路径都打印；媒体参数用 `ffprobe` 的 JSON 输出 |
| 中文 prompt 过 PowerShell 乱码 | 写进 `.txt` 用 `--prompt-file` |
| 中文/空格路径 | 走 `E:\vsf` junction；脚本用 `path.resolve`，不硬编码中文 |
| 参考图水印不总在左上 | 左下/右下也有；去水印前先探 |

## 7. 什么时候该并行开子代理

本项目**长期授权**主动并行（根 `AGENTS.md` 与用户级 `AGENTS.md`）。判据：

- **该扇出**：≥3 个互不依赖的子任务（批量看几十张图、多段出片核验）；单个子任务上下文很重
  （读长文件、反复试错）；结论需交叉验证（质量型验收的独立复核）。
- **不该扇出**：一两步、强依赖、必须靠连续对话上下文推进。

纪律：

1. **同一文件同一时间只有一个写者**，并行任务先声明写范围。
2. **花钱的并行必须主 agent 统一控账**，不把付费权下放给子代理。
3. **链式依赖必须串行**（下一段要用上一段末帧做首帧）。
4. 汇总后由主 agent 统一复核，不盲信任何单个子代理的结论。
