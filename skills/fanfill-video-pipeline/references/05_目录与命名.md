> **本文件定位**：建工作区、放产物、命名、归档、跨歌复用时看这里。
> **契约来源（唯一）**：`00_docs/08_翻填项目配置规范.md`（schema v1 · 2026-09-27 冻结）
> 与根目录 `翻填项目.json`。**本文件不得发明规范里没有的目录或字段**；两者冲突时以 `08` 为准。

## 0. 三条铁律（先记这个）

| # | 铁律 | 含义 |
|---|---|---|
| 1 | **新产物只新增** | 命名冲突自动加 `-2` / `-3` 后缀，**永不覆盖**同名文件 |
| 2 | **迭代替换先归档** | 旧产物移入 `<historyDir>/<时间戳>/` + README，新产物用 `vN` |
| 3 | **四个保护区零改动** | `01_input` / `02_stems` / `09_aceproject` / `music` —— agent 不删不改 |

配套的第 4 条（属于配置层）：**脚本零硬编码**，任何路径都从 `翻填项目.json` 的 `video.*Dir` 读，
脚本内部用 `path.resolve(workspaceRoot, rel)` 转本地路径。

### 2.2 `prompts\` —— 每段一个 `.txt`

```text
prompts\
├── NN_slug.skeleton.txt        骨架（含段头注释：段号/时间区间/段长/生成秒/模式/素材/接点/歌词）
├── NN_slug.txt                 三段式 prompt（T2VA / I2VA / FL2VA / L2VA）
└── ref2va\
    └── NN_slug.txt             六段式 Ref2VA prompt
```

- `NN` 两位序号，`slug` 与 `segments.json` 完全一致（`01_intro_title` … `17_out_credits`）。
- **优先级**：`ref2va/NN_slug.txt` 存在 → 该段走 Ref2VA；否则走 `NN_slug.txt`。
  → **改 prompt 前先确认该段实际用哪一份**（见 `references/03_prompt规范.md` §14）。
- 段头注释里的"生成 N 秒"是写 prompt 的硬约束（时间轴总长必须等于它）。

### 2.3 `refs\` —— 参考图

命名 **`ref_<原名>.jpg`**（保留原扩展名以外的原文件名，含括号）：

```text
refs\ref_星海绘卷.jpg   ref_然后向着明天.jpg   ref_薪火传承.jpg   ref_德丽莎2022生日.jpg
refs\ref_月下1.jpg      ref_月下3.jpg          ref_10th.jpg       ref_ElysianRealm.jpg
refs\ref_屏幕截图(115).jpg  ref_屏幕截图(163).jpg  ref_屏幕截图(321).jpg
```

- 由 `81_pv_refs.mjs` 生成：ffmpeg `delogo` 擦掉「崩坏3」logo → 缩放到 **1536 宽**（`scale='min(1536,iw)':-2:flags=lanczos`）→ `-q:v 3`。
- **水印位置要逐张探**：本歌 `81_pv_refs.mjs` 的 `NEEDED` 共 11 项，逐项核对为
  `logo: 'tl'`（左上）**4 张**（`德丽莎2022生日` / `星海绘卷` / `然后向着明天` / `薪火传承`）、
  `'br'`（右下）**2 张**（`10th.jpg`、`ElysianRealm.png`）、`false`（无水印）**5 张**
  （`屏幕截图(321)` / `屏幕截图(115)` / `屏幕截图(163)` / `月下1` / `月下3`）。4 + 2 + 5 = 11 ✅
  擦除区按原图尺寸比例算（左上 `0.145w × 0.105h`；右下 `0.30w × 0.10h`）。
  > **别照抄数字，也别默认水印在左上**：左下 / 右下都出现过。新增素材前先抽一帧看一眼，
  > 再决定该填 `tl` / `br` / `false`；擦错了会把水印留在参考图里，进而被 H3 画进成片。
- ⚠️ **`refs\` 里的图是产物，不是原图**。原图永远在 `01_input\CG\`（保护区）。
- ⚠️ 本歌实况：`refs\` 里 11 张，而 `81_pv_refs.mjs` 的 `NEEDED` 列表也是 11 项 —— **两边要一起更新**。

### 2.4 `clips\` —— 每段成片

命名 **`<两位序号>_<slug>.mp4`**：

```text
clips\01_intro_title.mp4  …  clips\17_out_credits.mp4        （17 段，全齐）
clips\frames\07_0_2.jpg   07_3_0.jpg   07_5_5.jpg            （抽帧复核）
clips\frames\AB_05_起点_原图vs成片.jpg  AB_07_薪炎_原图vs成片.jpg  （1:1 对照图）
clips\12_inter_a.mp4  13_inter_b.mp4                          （链式段）
```

- **衍生一切从 `clips\` 取帧**，不要从成片取（成片带字幕）。
- 段成片是 H3 原样产物（1344×768 / 24fps / 自带音轨）；音轨在 `84` 合成时丢弃。

### 2.5 `subs\` —— 字幕

| 文件 | 生成命令 | 用途 |
|---|---|---|
| `未来再见.ass` / `未来再见.srt` | `node scripts\83_pv_subs.mjs` | 768P 画布 |
| `未来再见_1080.ass` / `_1080.srt` | `node scripts\83_pv_subs.mjs --w 1920 --h 1080 --tag 1080` | 1080p 画布 |

- `--tag <T>` 的规则：`BASE = TAG ? '<歌名>_<TAG>' : '<歌名>'` → **不覆盖**低分辨率版。
- 字号按**基准尺寸**给，多分辨率时按比例缩放。
- 样式族：`Lyric` / `Title` / `Info` / `Small`，**字体必须唯一**（本歌 `Microsoft YaHei`）。

### 2.6 `cover\` —— 封面

```text
cover\
├── 封面_A_xinyan_1146x717.jpg      封面_A_xinyan_1344x768.jpg
├── 封面_B_moon_1146x717.jpg        封面_B_moon_1344x768.jpg
├── 封面_C_moonwide_1146x717.jpg    封面_C_moonwide_1344x768.jpg
├── 封面_D_10th_1146x717.jpg        封面_D_10th_1344x768.jpg
└── logos\  ace_icon.png  ace_logo.png  dsh_whale.png  minimax_MiniMaxLogo-Light.png  …
```

- 命名：**`封面_<版式>_<宽>x<高>.jpg`**；版式代号 `A/B/C/D…` + 内容词（`xinyan` / `moon` / `moonwide` / `10th`）。
- `cover.sizes` 必须含 B站规格 **`[1146, 717]`**；本歌另有原生 `[1344, 768]`。
- 中间文件落 `.tmp\cover_<版式>.png` / `.ass`（可删，不影响交付）。
- **官方 logo 引用不复制**：`cover.logos` 写路径（本歌指向 `cover/logos/`），跨歌共享时改成共享目录的路径。

## 5. `vN` 版本命名与 `history\<时间戳>\` 归档

### 5.1 `vN`

- 成片每次迭代**升版本号**：`未来再见_PV_v1.mp4` → `未来再见_PV_v2.mp4`。
- 配套产物同样带版本后缀：`cost_log_v1.csv`、`verify/report_v1.md`。
- **绝不用同名覆盖**；也不要用 `_final` / `_new` / `_修` 这类词（无法排序、无法判断新旧）。
- 交付索引写在配置的 `video.deliverables`：
  ```json
  "deliverables": {
    "pv": "10_h3video/pv/未来再见_PV_v2.mp4",
    "pv1080p": "10_h3video/pv/未来再见_PV_v2_1080p.mp4",
    "cover": "10_h3video/pv/cover/封面_D_10th_1146x717.jpg",
    "copy": "10_h3video/pv/投稿文案.md"
  }
  ```
  工作台直接读这几个字段，**不猜文件名**。升版本时要同步改这里。

### 5.2 什么时候归档

**在替换任何已成产物之前**（不只是成片）：

- 重出某段 → 覆盖 `clips\NN_slug.mp4` 之前；
- 改写某段 prompt → 覆盖 `prompts\NN_slug.txt` 之前；
- 重跑核验 / 重新合成 → 覆盖 `report.md` / 成片之前。

### 5.3 归档目录里放什么

本歌实例：`10_h3video\pv\history\20260927-233420\`

```text
history\20260927-233420\
├── README.md            ★ 必须：旧版是什么、为什么换、用户当时的指示原话
├── 未来再见_PV_v1.mp4      被替换的旧成片
├── clips\               被重出的 4 段旧成片（01 / 02 / 03 / 06）
├── prompts\             这 4 段的旧提示词备份
├── verify\report_v1.md  v1 核验报告（7/7 通过）
└── cost_log_v1.csv      v1 花费明细
```

`README.md` 的必备三问（本歌原文结构）：

```markdown
# 归档：PV v1（2026-09-27 20260927-233420）
本目录保存的是**被替换前**的产物，**只做保留、未删除**。
- <逐条列出目录里的旧产物 + 一句话说明它是什么>
## 本次改动原因（用户 2026-09-27 指示）
1. …（写用户原话/原意，不写自己的转述）
```

- **时间戳格式**：`YYYYMMDD-HHmmss`（本歌 `20260927-233420`）。
- **没有 README 的 history 目录等于没归档** —— 它是给下一个执行者看的变更说明，不是备份。

## 7. 中文路径规避：走 `E:\vsf` junction

- 本机已存在 junction：**`E:\vsf` → `E:\Videos\未来再见翻填`**（`LinkType: Junction`，已实测）。
- 用途：给**不喜欢中文/空格路径**的外部工具与命令一条纯 ASCII 路径。例如
  `90_loudness_check.ps1` 的官方用法就写作
  `powershell -NoProfile -ExecutionPolicy Bypass -File E:\vsf\scripts\90_loudness_check.ps1 -InFile "08_release\stage1_master.wav"`。
- **脚本纪律**：
  1. 一律 `const ROOT = process.cwd()`，再用 `path.join(ROOT, ...)` / `path.resolve(ROOT, rel)`；
  2. **绝不**在脚本里写 `E:\Videos\未来再见翻填` 这样的中文字面量；
  3. 配置里的 relpath 用 **POSIX 分隔符 `/`**，且**不得是绝对路径、不得含 `..`**（`08` 规范 §9 校验项 3）。
- 若 junction 丢失，用管理员 PowerShell 重建：
  ```powershell
  New-Item -ItemType Junction -Path E:\vsf -Target "E:\Videos\未来再见翻填"
  ```
  （**未实测重建**；本机现有 junction 是既存状态。）

## 8. 非破坏性红线与佐证方法

### 8.1 红线

`01_input\` / `02_stems\` / `09_aceproject\` / `music\` —— **agent 不删、不改、不移动**。
需要它们的产物时**读取并派生**到输出目录（`10_h3video\...`），不要原地改。

### 8.2 佐证方法（时间戳）

```powershell
foreach ($d in @("01_input","02_stems","09_aceproject","music")) {
  Write-Output "--- $d ---"
  Get-ChildItem "E:\Videos\未来再见翻填\$d" -Recurse -File |
    Sort-Object LastWriteTime -Descending | Select-Object -First 5 LastWriteTime, FullName |
    Format-Table -AutoSize
}
```

判读方式：**看"谁在什么时候动的"**，不是"目录时间戳是否全部早于开工"。

### 8.3 本机实况（照实记录，别误读）

保护区里**确实存在晚于 PV 开工的时间戳**：

| 文件 | 时间 | 来源 |
|---|---|---|
| `01_input\CG\ElysianRealm.png`（及 `1st/2nd/3rd/4th`） | 2026-09-27 23:13–23:16 | **用户自己新增的 CG**（`history\20260927-233420\README.md` 记有"段 06 改为参考 `ElysianRealm.png`"的用户指示） |
| `09_aceproject\初调\翻填.wav` / `翻填.Vocals.wav` | 2026-09-27 20:39–20:40 | 用户在 ACE Studio 侧重导出（工程归用户所有） |
| `music\陶典_hanser-未来再见-翻填.lrc` | 2026-09-27 20:45 | 用户侧更新 |

→ **结论**：`"零改动" 应理解为 "agent 零改动"**。
用时间戳佐证时，必须**先区分动作主体**（agent 的产物都落在输出目录；保护区的变化要能指出是用户行为），
否则会得出"红线被破了"的错误结论。
