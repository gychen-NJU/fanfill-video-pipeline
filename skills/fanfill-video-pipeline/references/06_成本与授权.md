## 0. 三条铁律

1. **一次总授权 + 逐笔台账**：用户给出总预算与总授权后，**不再逐步确认**——
   用户原话是"不要太多瓶颈"（`budget.authorizationNote` 也照此留痕）。
2. **只在预估会突破 `budget.totalCny` 时停下来问**。没超就继续干、继续记账。
3. **任何真实付费调用都要有兜底**：命令行 `--max-cost`、MCP `maxCostCny` + `confirmSpend`。兜底不是授权，授权是上一句。

**唯一花钱的阶段是 H3 出片**（`scripts/82_pv_clips.mjs`）。音乐线、字幕、合成、超分、封面、核验全是本地 ¥0。

### 2.3 失败与重试的真实代价

- **提交失败不计费**：段 8 头两次提交报 API 错（`cost_log.csv` 里费用列 `0`），第三次成功才扣 ¥6.50。
- **重出按段收费**：单段重出就是"再买一次这段的秒数"。`--only <段号>` 是唯一正确的重出入口，
  **不要为了改一段而重跑全片**（全片重跑 = ¥87 起）。
- ⚠️ **台账与逐次日志的段号口径要对齐**：台账第 4 行写"重出 段13 ¥6.50"，
  而 `cost_log.csv` 里"13 秒 / ¥6.50"的成交记录属于**段 8**（前两次失败、第三次成功）。
  两处**金额与累计一致**（9 + 71.5 + 22.5 + 6.5 = ¥109.50），但**段号对不上**；
  追溯单笔时以 `cost_log.csv` 的 `任务id` 为准，台账的"项目"栏要写清是首轮、重出还是补跑。

## 3. 授权纪律（照抄这个流程）

1. **开工先报总账**：名义时长 → 逐段向上取整的生成秒数 → 全片预估 → 加 15% 重试余量
   → 说明"重出按段收费"。（本歌首次报价：165.86 s → 174 s → **¥87.00**，含余量 ¥100.05。）
2. **拿一次总授权**，写进 `翻填项目.json`：

```jsonc
"budget": {
  "totalCny": 150,
  "spentCny": 109.5,
  "authorized": true,
  "authorizationNote": "用户 2026-09-27 一次总授权：PV 出片预算 ¥150，逐笔记台账，只在超预算时停。"
}
```

3. **之后不再逐步确认**。每批次结束只汇报三件事：**花了多少 / 累计多少 / 还剩多少**。
4. **只在预估会突破 `budget.totalCny` 时停下问**。此时给出选项（见 §4），不要只抛一个"钱不够了"。
5. `spentCny` 由台账汇总；脚本**只读不写**，除非显式 `--sync-budget`。

## 4. 选项化提问模板（**给选择题，不要问答题**）

每个选项必须写清 **当前值 / 可选值 / 对时间与成本的影响**。这是本项目的硬格式：

```text
分辨率：   768P（¥0.50/s） ｜ 1080p 本地超分（免费、+28 分钟） ｜ 2K 真出（¥0.80/s）
分离路线： ACE Studio（快、需开客户端） ｜ python-audio-separator（慢、纯本地）
转场：     硬切（免费） ｜ 0.4s 溶解（需重算时间轴）
重出范围： 只重出段 13（¥6.50、约 2 分钟） ｜ 重出段 12–13（¥11.50） ｜ 全片重跑（¥87 起）
```

反面写法（**不要这样问**）：
- ❌ "要 2K 吗？"（没给价、没给替代、没给时间）
- ❌ "预算可能不够，怎么办？"（把决策推给用户，却没给选项）
- ❌ 一步步问"这步要花钱，可以吗？"（违背"不要太多瓶颈"）

**默认推荐项放第一个**，并注明推荐理由：本项目的默认是
**768P 出片 + 本地 Real-ESRGAN 超分到 1080p**（¥0、只花 28 分钟），
2K 真出只在"必须原生 2K 细节"时才提。

## 5. 兜底手段（三层，全部要有）

| 层 | 手段 | 用法 |
|---|---|---|
| 命令行（`tools/minimax-h3/h3.mjs`） | `--max-cost <元>`、`--yes`、`--dry-run`、`--output json` | **默认 `--max-cost 5`**；超限直接拒绝执行。示例：`node h3.mjs run --prompt-file p.txt --duration 11 --resolution 768P --ratio 16:9 --out-dir 10_h3video/pv/clips --max-cost 5.51 --yes` |
| 批量脚本（`scripts/82_pv_clips.mjs`） | `--plan`（只打印计划与预算，**不发请求**）、`--max-cost`（**默认 78 元**）、`--only 09,10`、`--skip-done` | 回放/自检一律 `--plan`；单段调用时脚本自动把 `--max-cost` 收紧到 `genDur × 单价 + 0.01` |
| MCP（`mcp__h3__*`） | `h3_estimate_cost`（免费估算）、`h3_generate_video` 的 `maxCostCny`（默认 5）+ `confirmSpend` | 预估超 `maxCostCny` 时**必须显式传 `confirmSpend: true`**，否则工具直接拒单 |

**MCP 的 60 秒约束**：MCP 单次请求限 60 秒，而出片要 1–3 分钟 ——
必须"**提交 → 分次轮询**"（`h3_generate_video` 拿 `task_id`，再用 `h3_fetch_result` 分次取），
不要一次调用等到底（等到底会超时，任务却还在跑）。

## 6. 台账格式（固定列，不要改）

### 6.1 `_进度/成本台账.csv`（人读的总账）

列**固定**为：

```csv
时间,阶段,项目,金额CNY,累计CNY,备注
```

**本歌的真实样例行（逐字，勿改格式）**：

```csv
时间,阶段,项目,金额CNY,累计CNY,备注
2026-09-27 14:30,PV出片,段5+段7 试片,9.00,9.00,H3 768P 18s；验证链路可用
2026-09-27 14:45,PV出片,批量出片 段1-17（首轮）,71.50,80.50,H3 768P；段8 首两次提交失败未计费
2026-09-27 15:50,PV出片,重出 段1/2/3/6,22.50,103.00,改连续三镜版
2026-09-27 17:00,PV出片,重出 段13,6.50,109.50,修正末帧衔接
```

写法纪律：
- **一笔记一行**，一次批量出片算一笔；`累计CNY` 必须是**本次之后的总数**（自校验：最后一行 = `budget.spentCny`）。
- `备注` 写清**为什么花这笔**（试片/首轮/重出/补跑）与**口径**（多少秒、什么分辨率、是否含失败）。
- 文件编码 UTF-8；用 `read` 工具看，PowerShell 控制台直接 `Get-Content` 会显示成乱码（不影响文件本身）。

### 6.2 `<planDir>/cost_log.csv`（机器读的逐次尝试）

列**固定**为：`时间,段,模式,生成秒,费用元,任务id,成功,时长,备注`。
**失败也要记**（费用列写 `0`），这样才能解释"为什么 17 段的首轮只花了 ¥71.50"：

```csv
2026-09-27 14:44:57,1,base,11,5.50,446324601061674,1,11.54,""
2026-09-27 14:45:20,8,ref2va,13,0,,0,,"提交失败：…区域：cn (https://api.minimaxi.com)…"
2026-09-27 14:50:47,8,ref2va,13,6.50,446330026357021,1,13.67,""
```

- `任务id` 是**追溯单笔花费的唯一凭据**（对不上账时拿它去 `h3.mjs get <id>` / `h3_task_status` 复查）。
- 出片脚本**自动追加**这两个文件，不要手改历史行；要修正就追加一行并说明。

## 7. 省钱原则（顺序即优先级）

1. **本地免费优先**：超分、分离、混音、扒谱、字幕、合成、封面、核验全部用本机算力。
   - 超分：`node scripts/87_pv_upscale.mjs`（ffmpeg 抽帧 → Real-ESRGAN ncnn-vulkan ×2 → 超采样到 1920×1080 → 重烧字幕），
     **全程不调云 API**，代价只是 28.1 分钟墙钟。
     ⚠️ 脚本默认模型是 `realesr-animevideov3`，而配置里 `video.upscale.model` 写的是 `realesrgan-x4plus` —— 两者不一致，
     新歌改配置时以脚本默认值为准或显式 `--model`。
   - 分离：`scripts/10_separate.ps1`（¥0，GPU 约 1.1× 实时）。
2. **回放与自检一律 `--plan`**：`82_pv_clips.mjs --plan`、`87_pv_upscale.mjs --plan`、`80_pv_shotlist.mjs --plan`
   都只打印将要做什么与预估花费，**不发请求、不花钱**。核对分镜/字幕/报告时永远先用它们。
3. **只重出该重出的段**：`--only <段号>`；`--skip-done` 跳过已有成片。
   **不要**因为"顺手重跑一遍"烧掉 ¥87。
4. **失败不要紧，重复提交才要紧**：提交失败不计费，脚本会自动重试 ≤2 次；但每次重试都要落 `cost_log.csv`，
   避免"钱花了但没人知道花在哪"。
5. **并行省时间不省钱**：H3 允许 30 并发，非链式段可并行提交（墙钟从数小时压到 ~1.5 h），
   但**计费不变** —— 别把"并行"当成"便宜"。
6. **超分代替 2K**：1080p 交付用本地超分（¥0）而不是 2K 真出（≈¥139 全片）；
   只有在必须原生 2K 时才提 2K，且要让用户明确知道贵多少。
7. **便宜档先试片**：新歌或新 prompt 结构先出 1–2 段（本歌 ¥9.00 的试片验证了链路可用），
   确认观感再批量 —— 批量误判的代价是整片预算。

## 10. 留白与未实测（不要当成已验证）

- **2K 真出与 2K 再生成的实际扣费**：本歌**没做过**（全部 768P + 本地超分）。
  表里的 ¥0.80/s 与 ¥0.30/s 是工具/官方口径，**未经本机账单验证**。
- **`MiniMax-H3-Max` 全档**：本歌未使用；480P ¥0.33/s、768P ¥0.50/s 只作选型参考。
- **失败的扣费边界**：本歌只实证了"提交阶段报 API 错不计费"；**生成中途失败是否计费未实测**。
- **`estimate` 与实扣的偏差**：本歌 174 s 预估 ¥87.00 与实际首轮 143 s ¥71.50 不是同一口径对照，
  真正的"预估值 vs 账单值"1:1 核对**尚未做过**。
- **音乐线的钱**：本歌音乐线全程 ¥0（本地分离 + ACE 本地渲染）；
  ACE 侧唯一的付费点是 **Stem Splitter 的 `advanced` / `customized` 模式**（计费 SKU，本歌未使用），
  其余 ACE 动作（`vocal-to-midi` / `export` / `lyric fill` …）在本歌均为 ¥0 ——
  但**"哪些 ACE 功能消耗订阅额度"本机未逐项核实**，动了计费档之前先看 `acestudio-cli help`。
