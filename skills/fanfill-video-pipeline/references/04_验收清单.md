## 1. 七项硬核验（逐项：阈值 / 做法 / 本歌实测）

### 1.1 基本规格

| 项 | 阈值 | 做法 | 本歌实测 |
|---|---|---|---|
| 时长 | `song.totalSec ±0.05s`（本歌 165.86s） | `ffprobe -show_entries format=duration` | **165.875s** ✅ |
| 分辨率 | 与 `EXP_W × EXP_H` 严格相等 | `ffprobe -show_entries stream=width,height` | 1920×1080（1080p 版）/ 1344×768（768P 版）✅ |
| 帧率 | 恒 `24/1` | `ffprobe -show_entries stream=r_frame_rate` | `24/1` ✅ |
| 视频编码 | `h264` | `ffprobe -show_entries stream=codec_name` | `h264` ✅ |
| 音频编码 | `aac`（**必须有音轨**） | 同上，`codec_type=audio` 的流 | `aac` ✅ |

```powershell
& "E:\software\FFmpeg\ffmpeg-8.1.1-essentials_build\bin\ffprobe.exe" -v error `
  -show_entries format=duration,size,bit_rate `
  -show_entries stream=codec_type,codec_name,width,height,r_frame_rate,sample_rate,channels `
  -of json "10_h3video\pv\未来再见_PV_v2_1080p.mp4"
```

> 参考：`00_docs/05_PV制作流水线.md` §7 第 1 条；H3 出片本身是 24fps + 32kHz 立体声 AAC，
> 但**成片音轨必须换成母版**（`09_aceproject/初调/翻填.wav`），H3 自带音轨在 `84_pv_assemble.mjs` 归一化时丢弃。

### 1.2 响度

| 项 | 阈值 | 本歌实测 |
|---|---|---|
| 整体响度 I | `−14 ±1 LUFS` | **−14.1 LUFS** ✅ |
| 真峰值 TP | `≤ −1 dBTP` | **−1 dBFS**（ebur128 口径）✅ |

```powershell
# 成片口径（与 85 脚本一致）
& "E:\software\FFmpeg\ffmpeg-8.1.1-essentials_build\bin\ffmpeg.exe" -hide_banner -i "<成片>.mp4" `
  -af "ebur128=peak=true" -f null NUL

# 音频线口径（发布前必跑；注意参数名是 -InFile，不是 -Input —— $Input 是 PowerShell 自动变量，踩过）
powershell -NoProfile -ExecutionPolicy Bypass -File E:\vsf\scripts\90_loudness_check.ps1 -InFile "08_release\stage1_master.wav"
```

> ⚠️ **踩过的坑**：`ebur128` 的逐帧日志里**也有 `I:`**（起始静音时是 `-70`）。
> 解析时必须只取最后的**汇总块**：

```js
const iM  = ltxt.match(/Integrated loudness:\s*\n\s*I:\s*(-?[\d.]+)\s*LUFS/)
const tpM = ltxt.match(/True peak:\s*\n\s*Peak:\s*(-?[\d.]+)\s*dBFS/)
```

> `90_loudness_check.ps1` 走的是 `loudnorm=...:print_format=json`，读 `input_i` / `input_tp` / `input_lra`，
> 阈值同样是 I ∈ −14±1、TP ≤ −1。**两个口径都要过**（母版一次、成片一次）。

本歌四个指定点（来自需求 4.1–4.4，写死在 `85_pv_verify.mjs` 的 `MANDATED`）：

| 时间 | 段 | 要求 | 文件 |

### 1.4 字幕

| 项 | 阈值 | 本歌实测 |
|---|---|---|
| 歌词行数 | `24/24`（每句歌词都出现在 ASS 里） | 24/24 ✅ |
| 字体一致性 | **单一字体** | `Microsoft YaHei` ✅ |
| 样式 | 多用途样式可共存，但字体必须同一个 | `Lyric/Microsoft YaHei`、`Title/Microsoft YaHei`、`Info/Microsoft YaHei`、`Small/Microsoft YaHei` |

```js
// 85_pv_verify.mjs 的判法
const styles = [...assText.matchAll(/^Style:\s*([^,]+),([^,]+)/gm)].map(m => `${m[1]}/${m[2]}`)
const missingLines = lyrics.filter(L => !assText.includes(L.text))
// 行数：lyrics.length - missingLines.length === lyrics.length
// 字体：new Set(styles.map(s => s.split('/')[1])).size === 1
```

> **多分辨率纪律**：字幕必须**在目标分辨率重烧**，不能放大已烧录的成片。
> 1080p 版用 `node scripts\83_pv_subs.mjs --w 1920 --h 1080 --tag 1080` 生成 `未来再见_1080.ass`，
> 再 `84 --timeline .up\timeline_1080.mp4 --ass subs\未来再见_1080.ass`。
> **`85` 默认读的是 `subs\未来再见.ass`（768 版）** —— 核 1080p 前先确认这一条指向正确，否则是在替错文件背书。

### 1.5 原创性（成片帧 vs 参考原图）

| 项 | 阈值 | 本歌实测 |
|---|---|---|
| 抽样最大 SSIM | **< 0.90** | **0.522**（34s 帧 vs `ref_德丽莎2022生日.jpg`）✅ |

做法：

```powershell
# 1) 每 4 秒抽 1 帧 → verify\samples\f_%03d.jpg（165.875s → 41 帧）
& $FFMPEG -y -v error -i "<成片>.mp4" -vf "fps=1/4" -q:v 3 "10_h3video\pv\verify\samples\f_%03d.jpg"

# 2) 每帧按其所在段，与该段的参考图比 SSIM（双方先缩到 672x384）
& $FFMPEG -hide_banner -i "<帧>.jpg" -i "10_h3video\pv\refs\<ref>.jpg" `
  -lavfi "[0:v]scale=672:384[x];[1:v]scale=672:384[y];[x][y]ssim" -f null NUL
# 取 stderr 里的 All:0.xxxxxx
```

**判读方向**：SSIM **越低越"二创"**（说明成片不是把原图搬进来）。所以阈值是**上限** 0.90，不是下限。
段 → 参考图的映射表（`REFMAP`）写在 `85_pv_verify.mjs` 与 `82_pv_clips.mjs` 里，两处**必须一致**。

> `T2VA` 段（无参考图）不参与这项比较；`REFMAP` 里没有的段会被 `continue` 跳过。

### 1.6 段间接缝（相邻段末帧 / 首帧 SSIM）

做法：抽 A 段末帧（`-sseof -0.2`）与 B 段首帧（`-ss 0.05`），比 SSIM，出**全表**。

| 阈值 | 适用 | 本歌 |
|---|---|---|
| **≥ 0.60** | **链式衔接接点**（`CHAINED = {12, 13}`） | 0.788 / 0.885 ✅ |
| 不设阈值，只报数 | 其余接点 | 见 §2 全表 |

```powershell
& $FFMPEG -y -v error -sseof -0.2 -i "10_h3video\pv\clips\11_bridge_wake.mp4" -frames:v 1 -q:v 2 "10_h3video\pv\verify\_j11_last.jpg"
& $FFMPEG -y -v error -ss 0.05  -i "10_h3video\pv\clips\12_inter_a.mp4"    -frames:v 1 -q:v 2 "10_h3video\pv\verify\_j12_first.jpg"
& $FFMPEG -hide_banner -i "...\_j11_last.jpg" -i "...\_j12_first.jpg" -lavfi "[0:v]scale=672:384[x];[1:v]scale=672:384[y];[x][y]ssim" -f null NUL
```

### 2.2 三条判读规则

1. **高的四个（0.866 / 0.929 / 0.788 / 0.885）不是巧合**：
   1→2 与 2→3 是前奏三镜的**链式续拍**（`CHAIN = {2:1, 3:2, 12:11, 13:12}`），
   11→12 / 12→13 是间奏的链式续拍 —— 下一段的首帧**就是**上一段的末帧，所以必然高。
2. **低的那些（0.32–0.47）是正常且期望的**：本片转场以**硬切**为主，
   硬切两端的画面本来就该**完全不同**（换场景、换机位、换时间），SSIM 低恰恰说明切得开。
   **不要把它当成"接缝没接好"**。
3. **自动阈值只对链式接点生效**：`85_pv_verify.mjs` 里

   ```js
   const CHAINED = new Set([12, 13])
   const ok = s == null ? false : (isChain ? s >= 0.60 : true)
   ```

   即：**12 / 13 两个接点低于 0.60 才判失败**；其余接点只报数，靠人判断是否与"这一刀该怎么切"相符。

> **表格里的"类型"列来自分镜的 `transition` 字段（计划值）**，而实作是硬切
> （`00_docs/05_PV制作流水线.md` §8.1：`xfade` 会缩短总时长、破坏与歌词的逐句对齐，所以改用 concat 硬切）。
> 所以看到"转场"二字时，理解成"计划做溶解的接点"，别理解成"实做了溶解"。

## 3. 质量型需求：1:1 对比规则（**不能拿"参数达标"交差**）

### 3.1 规则

> 用户说"**更清晰 / 更好听 / 画质再高点 / 声音更亮**"这类**主观质量型需求**时，
> **必须做同帧 / 同段的 1:1 对比**，并**把对比材料本身交付给用户**。
> 只报"分辨率从 768 提到 1080、响度 −14.1 LUFS"是**无效交付**。

判据（缺一不可）：

1. 有**同帧**（画面）或**同段**（音频）的对照材料；
2. 对照材料落盘、路径可点；
3. 结论里写清"**看/听出来的差别是什么**"，而不只是"参数是多少"。

### 3.2 画面 1:1 对照（做法与真实产物）

本歌已有 3 张对照图（`10_h3video/pv/clips/frames/`）：

- `AB_05_起点_原图vs成片.jpg`
- `AB_05_终点_原图vs成片.jpg`
- `AB_07_薪炎_原图vs成片.jpg`

实测形态：**1344×384**＝左 672×384（参考原图）+ 右 672×384（成片同帧）左右并排，无标注文字。

推荐做法（两步，先抽帧再拼）：

```powershell
$F = "E:\software\FFmpeg\ffmpeg-8.1.1-essentials_build\bin\ffmpeg.exe"

# ① 从 clips（不是成片！成片带字幕，取帧会带字幕进去）抽同帧
& $F -y -v error -ss 3.0 -i "10_h3video\pv\clips\07_v1_xinyan.mp4" -frames:v 1 -q:v 2 "10_h3video\pv\.tmp\seg07_f3.jpg"

# ② 左原图 / 右成片，等宽并排
& $F -y -v error -i "10_h3video\pv\refs\ref_薪火传承.jpg" -i "10_h3video\pv\.tmp\seg07_f3.jpg" `
  -filter_complex "[0:v]scale=672:384:force_original_aspect_ratio=decrease,pad=672:384:(ow-iw)/2:(oh-ih)/2[v0];[1:v]scale=672:384:force_original_aspect_ratio=decrease,pad=672:384:(ow-iw)/2:(oh-ih)/2[v1];[v0][v1]hstack=inputs=2[out]" `
  -map "[out]" -q:v 2 "10_h3video\pv\clips\frames\AB_07_薪炎_原图vs成片_2.jpg"
```

> **铁律**：衍生物料**不能从成片取帧**（成片已烧字幕）。要对照就**从 `<clipDir>/` 取**。
> 例外：`85_pv_verify.mjs` 的 `mandated_*` 与 `check_*` 抽帧是**故意从成片抽的** ——
> 它们要复核的正是"带字幕的最终观感"。

### 3.3 音频 1:1 对照（做法与真实产物）

本歌的 A/B 素材散落在 `07_mix\` 与 `08_release\`（`ab_*.wav`），命名形如
`ab_derisa_chorus_30k.wav` / `ab_derisa_chorus_original.wav`、`ab_ace_conv.wav` / `ab_ace_src.wav`、
`ab_melody_chorus_ace.wav` / `ab_melody_chorus_midi.wav`。

规则：

1. **同段切片**：同一句歌词切同一时间区间（不要一个听整段、另一个只听高潮）；
2. **先对齐响度再比音色/清晰度**：
   ```powershell
   & $F -i "A.wav" -af "loudnorm=I=-14:TP=-1.5:LRA=11" -ar 48000 A_norm.wav
   & $F -i "B.wav" -af "loudnorm=I=-14:TP=-1.5:LRA=11" -ar 48000 B_norm.wav
   ```
3. 对照结论写清"**哪个频段/哪个字更清楚**"，而不是"LUFS 都是 −14"。

### 3.4 什么算"质量型需求"（触发本节的词）

更清晰 / 更清楚 / 更好听 / 更亮 / 更厚 / 画质再高点 / 分辨率不够 / 糊 / 闷 / 刺耳 / 像不像原唱 /
"这次比上次好点没" —— 命中任一个，就走 §3，不要走 §1。

## 4. "验收全绿 ≠ 目标达成"

### 4.1 为什么

`85_pv_verify.mjs` 的 7 项全是**可计算量**：时长、分辨率、帧率、编码、响度、SSIM、字幕行数。
**它们一个都不回答"用户要的那一帧画面对不对"**。

| 会漏掉的问题 | 7 项核验看得出来吗 |
|---|---|
| 48s 那一帧**不是**"星海绘卷 → 然后向着明天"的转化瞬间 | ❌ 看不出来（只要画面存在、SSIM 达标就算过） |
| 角色**换了衣服 / 少了一台机甲 / 武器拿错手** | ❌ 看不出来 |
| 画面里出现了**文字/水印** | ❌ 看不出来（`80b` 只查 prompt，不查成片） |
| 转场生硬、节奏与歌词不搭 | ❌ 看不出来 |
| 字幕**断句**难看、挂得太久 | 部分（只查行数与字体，不查可读性） |

> 本歌的真实教训（`00_docs/04_MiniMax-H3视频生成工作流.md` §3.4）：试片抽了 0.5s / 2.5s / 4.5s 三帧，
> **画面与 prompt 高度吻合**，但 2.5s 与 4.5s 两帧差异偏小 —— "动作没发生"这件事，
> **任何 SSIM/规格数字都测不出来**，是**人眼看出来**的。

### 4.2 必做：指定画面的人眼复核（三步）

1. **逐张对照需求原句**：打开 `verify/mandated_*.jpg`，对每一张写下"需求句 → 图里对应的像素证据"。
   例如 68s 要"薪炎永燃"：图里必须有**举剑 + 金色环状符文 + 火星上升 + 冷暗背景**这几项；
   少一项就写"部分满足 + 缺什么"。
2. **抽边界帧**：每段至少再看**首帧 / 中帧 / 末帧**（`clips/frames/` 已有 `NN_0_3.jpg` / `NN_x_x.jpg` 形态的产物）。
   末帧尤其重要 —— 它是下一段链式的输入。
3. **结论必须写"不足"**：汇报时如实说"哪一镜不达预期、重出要多少钱"（本歌 768P 重出一段 ¥0.5/s）。
   **不许用"7/7 全过"掩盖画面问题。**

### 4.3 汇报模板

```text

硬核验：7/7 ✅（时长 165.875s / −14.1 LUFS / 最大 SSIM 0.522 / 链式 0.788·0.885）
```
