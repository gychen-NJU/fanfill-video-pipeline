## 2. 分离：两条路线

### 2.1 路线 A · python-audio-separator + BS-Roformer（**本歌实际路线**）

环境 `venvs\sep`（Python 3.12.13 + torch 2.9.1+cu126 + audio-separator 0.47.0），重建：`scripts\20_setup_sep.ps1`。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File E:\vsf\scripts\10_separate.ps1 -InFile "01_input\原曲.mp3"
# 可选：-OutDir "02_stems"（默认） -Model "model_bs_roformer_ep_317_sdr_12.9755.ckpt" -Format WAV
```

- **默认模型** `model_bs_roformer_ep_317_sdr_12.9755.ckpt`（BS-Roformer，SDR **12.98**，首次运行自动下 639MB 到 `cache\hf`）。
- **自动预处理**：输入不是 `.wav`/`.flac` 时脚本先用 ffmpeg 转 44.1kHz 立体声 WAV —— 必须这样做：
  `audio-separator` 内部走 librosa→libsndfile，本机读 MP3 直接抛 `LibsndfileError: Unspecified internal error`（换 ASCII 名也一样）。
- **产物**：`02_stems/song_(Vocals)_model_bs_roformer_ep_317_sdr_12.wav`（干声）与
  `…_(Instrumental)_…wav`（伴奏）。名字取自输入文件名 + 模型名（被截断）；本歌实跑输入 `01_input/song.mp3`，故前缀是 `song_`。
- **实测速度**：30 秒素材 **34 秒**（含 33 秒模型加载）；真实原曲（163.69 s / 44.1kHz 立体声 / 320kbps）
  **3 分 01 秒**（≈1.1× 实时），GPU 利用率 **99%**、显存峰值 **3347 MiB**。
- **量化验收**：`scripts\12_check_separation.py` 出 SI-SDR + 最佳时延 + 相关系数。⚠️ 本项目的 50.72 dB 是
  "三正弦伴奏 + 真值清唱"的**送分题**，只证明链路正确（零时延还原），**不代表真实歌曲质量上限** → 真实歌曲必须**听感验收**：
  ① 伴奏有无原唱残留（和声/气声/尾音）？② 干声有无伴奏漏音（会拖累扒谱）？

### 2.2 路线 B · ACE Studio 自带 Stem Splitter（快、需开客户端）

前置：**ACE Studio 必须正在运行**（CLI 直连进程）。音频先在工程里成为 clip：

```powershell
# 1) 导入（扩展名决定类型：wav/mp3/flac… → Audio clip）
acestudio-cli import file --path "E:\Videos\未来再见翻填\01_input\原曲.mp3" --track-index 0 --json
# 2) 拿 clip UUID（clip 列表或上一步返回里都有）；一次一个 clip，一个 clip 一个 job
acestudio-cli generative stem-splitter --clip-uuid <CLIP-UUID> --mode basic --wait --json
# 3) 多结果投递：分轨落在源 clip 下方新建的轨道里，job get 看哪几条已落地
acestudio-cli job get <JOB-ID>
# 4) 要落成文件，再按轨导出
acestudio-cli export audio --path "E:\Videos\未来再见翻填\02_stems\ace_vocals.wav" --scope tracks --track-uuid <TRACK-UUID> --format wav --sample-rate 44100 --wait
```

| `--mode` | 分出什么 | 计费 |
|---|---|---|
| `basic`（默认） | vocal + instrumental | **免费** |
| `professional` | vocal / drums / bass / piano / guitar / others | **免费** |
| `advanced` | 模型能认出的全部（约十余条） | **计费**（advanced SKU） |
| `customized` | `--prompt` 指定的音色 + 其余全部 | **计费**（customized SKU） |

`--remove-reverb <bool>` 只在 `basic`/`professional` 可用（**人声混响太重时的第一手段**）；`--prompt` 只在 `customized` 可用且必填。
`--mode` 不会自动推断（选模式就是选花不花钱），额度不足回 `CREDIT_INSUFFICIENT`。
导出走 job 模型：**exit 0 只代表提交成功**，音频还没落盘，必须 `job wait` / `job list` 轮询到 `succeeded`。

### 2.3 怎么选

| 判据 | 选 A（python-audio-separator） | 选 B（ACE Stem Splitter） |
|---|---|---|
| 无人值守 / 批量 / 脚本化 | ✅ 纯命令行、幂等、可重跑 | ⚠️ 需 Studio 在运行，作业异步 |

| 要 6 轨以上细分 | 需换模型 | ✅ `professional` 免费给 6 轨 |
| 花钱 | ¥0 | `basic`/`professional` ¥0；`advanced`/`customized` 计费 |

**默认走 A**（`audio.separation = "python-audio-separator"`）；只有"人声混响太重想去混响"或"已在 Studio 里"才用 B 的免费档。

## 3. 扒谱：拿到"音符骨架"

### 3.1 路线 A · ACE `vocal-to-midi`（**最准，本歌主力**）

```powershell
acestudio-cli generative vocal-to-midi --clip-uuid <干声 CLIP-UUID> --language chinese --apply-pitch true --json
acestudio-cli job wait <JOB-ID>                                        # 或启动时加 --wait
acestudio-cli clip note-content --track-index 1 --clip-index 0 --json  # 回读音符与音节
```

`--language` **必填**（服务无自动检测）：`chinese`/`english`/`japanese`/…/`notes-only`。
`--apply-pitch true`（默认）把**原唱音高曲线**带到音符上；`false` 给规整标称音高（打算重新演绎旋律时才用）。
结果落在一条 Sing 轨（`--track-uuid` 可选，不给就插在源 clip 下方新建一条）。

**本歌实测**：从干声扒出 **219 个音符** = 201 个汉字音符（= 翻填字数）+ 8 个 `a` 衬词（前奏哼唱）+ 10 个 `-` 延音标记。
⚠️ **汉字音符 ≠ 1:1 对应字数**：原唱有"一字跨多音"的拖腔、有"陪陪"这类**假拖腔**（听错）、偶尔漏认音节 ——
按"一音一字"硬铺会整句错位（实测第 14 行错位一个音符）。对位必须按 §5.3 的脚本组合做。

## 4. 对齐版 MIDI 的 tick 规则（最容易踩死的一节）

### 4.1 为什么工程 tempo 是 156

实测 78.3 与 156.6 是**同一张时间网格的两种记法**：网格间距都是 **95.8 ms**，残差都是 **20.1 ms**
（`scripts\17_bpm_refine.py` 梳状滤波精扫；`scripts\32_render_bpm_test.ps1` 也实测"按哪个 BPM 换算拍值，时间轴都等于原曲"）。
真正有区别的是**编辑网格疏密**：156 下一个汉字 ≈ 0.67 拍（八分音符）更好编辑，78.3 太粗。**所以工程取 156**
（`song.bpm = 156`，用户的 ACE 工程也是 156）。

### 4.2 ACE 导入 MIDI 的语义（决定 tick 怎么写）

- ACE 导入 note clip 时**用工程 tempo 解释文件里的 tick**，**文件自带 tempo 不被采用**
  （导入返回 `tempoImported: false`；CLI 侧开关 `import file --with-tempo <bool>` **默认 off**，且只对工程文件生效）。
- 推论：**文件声明的 tempo 必须与目标工程一致**，否则整首被按比例缩放 —— 本歌反例：下载的 `未来再见.mid` 声明 **120**，
  直接导进 156 的工程会被压成 0.769 倍，听起来就是"错位"。
- tick 换算：**官方口径**（`acestudio-cli help tick-coordinates` 原文）—— ACE 固定 **480 ticks per quarter note（PPQN）**，全工程恒定、**不随 tempo/拍号变化**；"tick → 秒"依赖 **tempo automation**，所以**不能只凭一个 BPM 值硬算**。
  本歌在 156 BPM 下即 **1248 tick/秒**（= 480 × 156 / 60），与 `scripts\65_ace_fix_and_verify.py` 的 `TPS = 1248.0` 一致。
  要桥接"秒 ↔ tick"请用官方换算命令（会走完整 tempo 曲线）：
  ```powershell
  acestudio-cli convert tick-to-time --tick <T>
  acestudio-cli convert time-to-tick --time <S>
  ```

### 4.3 `01_input/未来再见_对齐版_156BPM.mid` 的来由

`scripts\67_make_aligned_midi.py`（`--offset -6.708 --tempo 156`）做两件事，缺一不可：

1. **恒定偏移校正**：原文件整体比原曲**晚 +6.708 s**（**中位数最优化**扫出来的；端点法估的 −6.882 s 差 **174 ms**，不能用）。
2. **按目标工程 tempo 重写 tick**：新文件按 **156 BPM** 写 tick → 在 156 的工程里位置正确；
   且它自洽（声明 156 与音符真实节拍一致），丢进任何 DAW 也对。

产物 `01_input/未来再见_对齐版_156BPM.mid`（+ 副本 `07_mix/未来再见_对齐版_156BPM.mid`）。
实测：1474 字节；201 音符；范围 **30.855–157.886 s**；声明 156；**原文件 SHA256 未变**（脚本自校验并打印）。
选它当对位锚点的理由：它是**干净的"一字一音"**（201 音符 ↔ 201 字），没有拖腔歧义、没有听错丢字。

### 4.4 从词格表造 MIDI（`scripts\60_grid_to_midi.py`）

产物 `07_mix/grid_v4.mid` + `grid_v4_lyrics.txt`（201 字歌词串，直接喂 `lyric fill`）+ `grid_v4_manifest.csv`（序号↔字核对表）。
**必守规则（实测坑）**：**后一个音的头是硬边界，前一个音的尾不得越过它**（留 5 ms 余量）。
MIDI 导入器（含 ACE）遇重叠/同起点会丢音或合并 —— 实测 201 字进去只剩 **200 个音符**；
脚本里的消重叠循环就是为它，写完必须核对"消除重叠 N 处 / 音符数 M"。

## 5. ACE 出人声（建工程 → 先设 tempo 再导入 → 载声库 → 铺词 → 导出）

### 5.0 前置与纪律

CLI = `C:\Program Files\ACE Studio\acestudio-cli.exe`（v0.17.0 / ACE Studio 2.1.8），**直连正在运行的 Studio**；
`-y` 免确认，`--json` 让 stdout 只出 JSON，**不吃透语法就先 `help`**（`help <command>` / `help --search <regex>`，离线可查）。
**`09_aceproject/` 是只读保护区**（本歌在 `09_aceproject/初调/`，含 `初调.acep`、`初调.wav`、`翻填.wav`、`翻填.Vocals.wav`、
`Samples/`、`mvsession/`、`autosave/`）：要试就 `project save-as` 到别处，**不要原地改用户的工程**；动它之前先 `project dirty` 查未保存改动。

### 5.1 建工程 → 设 tempo → 导入（顺序不能换）

```powershell
acestudio-cli project new --json                                   # 或 project open --path <你的 .acep>
acestudio-cli project info --json                                  # 核对工程名/路径
acestudio-cli tempo set --points '[{"pos":0,"value":156}]' --json  # ← 先设速（整表替换语义）
acestudio-cli import file --path "E:\Videos\未来再见翻填\07_mix\未来再见_翻填_ACE.mid" --track-index 0 --json
# 不加 --with-tempo（默认 off）；MIDI 的 tick 已按 156 写死（§4）
```

`tempo set` 是**整表替换**（没列出的点全删），点按 `pos` 升序且不得重复，超出 minBpm/maxBpm 会自动放宽。
导入是**一个源轨一个 note clip**，返回里给 `clips`。

### 5.2 载声库（**换声库会重置歌词**）

```powershell
acestudio-cli voice load --track-index 0 --source "小夜" --json    # --source 用声库显示名（或 ref）
```

挂声库时若该轨是 MIDI 轨，会被转成 Sing 轨（与应用内一致）。
⚠️ **换声库会重置已铺的歌词** → 纪律：**每次 `voice load` 之后必须回读校验，不一致就重铺**
（本歌实测踩过；`scripts\61/63/66` 的"铺词 → 回读"成对结构就是为它准备的）。
本歌试听过的中文原生女声（`scripts\62_ace_voice_audition.py`，试听窗 **78.4–88.5 s**，每声库同一段，

## 7. 混音与响度（目标 −14 LUFS / TP ≤ −1 dBTP，双 PASS）

### 7.1 目标口径（以配置为准）

`audio.loudness = { "iLufs": -14, "toleranceLufs": 1, "truePeakDbtp": -1 }`。
比 −14 更响的母带，平台转码时 TP 需求更严（行业口径 < −2 dBTP），本项目统一按 **TP ≤ −1 dBTP** 收。

### 7.2 混音命令（本歌实际的两种落法）

```powershell
# ① ACE 工程内混（人声轨 + 伴奏轨）→ 直接导出成品 09_aceproject/初调/翻填.wav
# ② 命令行贴混（scripts\62_ace_voice_audition.py 的 mix()，本歌用于出 08_release 母带）
ffmpeg -y -v error -i "02_stems\song_(Instrumental)_model_bs_roformer_ep_317_sdr_12.wav" -i "<人声.wav>" -filter_complex "[1:a]volume=1.5[v];[0:a][v]amix=inputs=2:duration=first:normalize=0" -ar 44100 -ac 2 "07_mix\_tmp_mix.wav"
ffmpeg -y -v error -i "07_mix\_tmp_mix.wav" -af "loudnorm=I=-14:TP=-1.5:LRA=11" -ar 48000 -c:a pcm_s24le "08_release\ACE_master_fixed.wav"
```

要点：`loudnorm` 的 **TP 取 −1.5** 而不是 −1（给编码留余量，实测成品 TP 落 −1.4 ~ −1.5，稳过）；
`-c:a pcm_s24le` + `-ar 48000` 是交付规格（24bit/48kHz）。

### 7.3 校验（双 PASS）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File E:\vsf\scripts\90_loudness_check.ps1 -InFile "08_release\ACE_master_fixed.wav"
```

脚本用 `ffmpeg -af loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json -f null -` 量，打印三行并在行尾给 PASS/FAIL：
`integrated`（目标 −14 ±1）、`true peak`（目标 ≤ −1）、`LRA`。
**双 PASS 的落法**：PASS 1 量**原始混音** → 按 §7.2 归一化 → PASS 2 量**归一化后的成品**；
两次都要满足 −14 ±1 LUFS 且 TP ≤ −1 dBTP 才算过（只量一次不能放行，归一化本身可能带来削顶）。

## 9. 常见坑（音乐线）

| 症状 | 真因 | 处置 |
|---|---|---|
| 分离一启动就 `LibsndfileError` | audio-separator 内部 libsndfile 读 MP3 失败 | 先用 ffmpeg 转 WAV（`10_separate.ps1` 已内置） |
| 参数传了没生效（路径变 `E:\vsf\`） | 用 `$Input` / `$Args` 自动变量当参数名 | 改名 `-InFile` / `-ArgList` |
| MIDI 导入后少一个音符 | 音符重叠/同起点被导入器合并 | 前音尾不得越过后音头（留 5 ms），`60_grid_to_midi.py` 已做 |
| 导入后整首"错位/被压缩" | 文件 tempo ≠ 工程 tempo（tick 被按比例解释） | **先设工程 tempo 再导入**；文件按工程 tempo 写 tick（§4） |
| 对位整体差几百毫秒 | 用端点法估偏移 | 用**中位数最优化**扫恒定偏移（本歌 −6.708 s，端点法差 174 ms） |
| 某行的字被挤到很短的音符上 | 拖腔被当成"一音一字" | 用 `64` 按音节 DP 对齐，**只补空位不覆盖** |
| 换了声库后歌词全没了 | ACE 载声库会重置歌词 | 每次 `voice load` 后**重铺 + 回读校验** |
| `export audio` 秒退但文件不存在 | exit 0 只代表任务提交成功 | `job wait <JOB-ID>` / `job list` 轮询到 `succeeded` |
| 环境类报错（`audioread` 缺失 / `pkg_resources` / torch 装成 `+cpu` / `.ps1` 中文乱码 / `--user-data-dir` 吃参数） | 依赖与编码坑 | 见 `00_docs/00_环境与安装账本.md` §4 与 `scripts\20·21_setup_*.ps1` |
