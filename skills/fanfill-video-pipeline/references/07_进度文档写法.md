# 07 · 进度文档写法（`_进度/进度.md`）

> 本文是**格式层**：模板、状态符号、四条硬规则、写与不写的边界。流程顺序见 `SKILL.md`，不在这里重复。
> 规范出处：`00_docs/06_翻填视频工作流_开发计划.md` §5.5「进度文档规范」（用户明确要求）+ §8.2「状态文件」。
> 何时读：**每次要写 `_进度/进度.md` 时**（SKILL.md §0 第 1 条、§4）。

---

## 0. 为什么要有这一份

### 0.1 用户的原话

> 「**中间产物靠翻聊天记录才能找到**：用户明确要求过"**要明确的文件位置**"。」
> —— `00_docs/06_翻填视频工作流_开发计划.md` §1.1 现状痛点第 3 条

这就是 `进度.md` 存在的唯一理由：**把所有产物的位置锚定在一个不会消失的文件里**。

### 0.2 它是唯一入口

用户想知道"做到哪了、东西在哪、花了多少"，**只看这一个文件**。
数据层的另外三份（`<planDir>/segments.json`、`_进度/成本台账.csv`、`<planDir>/cost_log.csv`）都是**机器可读**的
（脚本与工作台读），不承担"给人讲清楚"的职责。不要再造第二份"进度.txt"或"STATUS.md"。

### 0.3 与记忆库的分工（**不要双写负担**）

> 「打分：**进度.md 是项目内、给用户看的**；跨会话结论才写记忆库。不要双写负担。」
> —— `SKILL.md` §4

| 写哪儿 | 写什么 | 例子 |
|---|---|---|
| `进度.md` | 本项目的事实：阶段、产物路径、验收数字、逐笔花费 | 「段 13 重出，`clips/13_inter_b.mp4`，¥6.50，末帧 SSIM 0.885」 |
| 记忆库 | 跨会话、跨项目都成立的结论与教训 | 「H3 单条 prompt 上限 7000 字符」「Ref2VA 与首帧图互斥」 |

**判别法**：换一首歌还成立 → 记忆库（或技能 `references/`）；只对这首歌成立 → `进度.md`。
**反面例子**：把 17 段的路径表抄进记忆库（噪音，且会立刻过期）。

### 0.4 它是断点续做的**唯一事实来源**

`SKILL.md` §0 第 1 条要求开工第一件事就是读它：

> 「读 `<工作区>/_进度/进度.md`。不存在就按 `references/07_进度文档写法.md` 建一个。
> 这是断点续做的事实来源——**不要从头重来，不要凭记忆猜做到哪了**。」

所以它必须**随时是最新的**。批操作结束不写，下一个会话就会重做已经做过的事、重花已经花过的钱。

> ⚠️ **已知缺口**：本歌（《未来再见》）在开发计划执行前 `_进度/` **只有 `成本台账.csv`**，没有进度文档
> ——而 `SKILL.md` §0 要求先读它。§1 的模板即用于补建。新歌必须**开工就建**，不要等做完再追记。

## 1. 完整模板

## 2. 逐块解释

### 2.1 标题行 `# <歌名> · 制作进度`

**一个工作区一首歌**，标题就是歌名，不要写"项目进度""工作进度"这类模糊词——工作台与人工检索都靠它认出这是哪首歌。

### 2.2 头部引用行（**三件事，一行说完**）

```markdown
> 最后更新：2026-09-27 17:42 ｜ 当前阶段：**PV 已完成交付（17/17）** ｜ 累计花费：¥109.50
```

| 字段 | 规则 |
|---|---|
| `最后更新` | **绝对时间**（`YYYY-MM-DD HH:MM`），不是"刚才""昨天"。每次追加都要改 |
| `当前阶段` | 一句话说清**断点在哪**。有分母就写分母（`出片（进行中 13/17）`），已完成写"已完成交付" |
| `累计花费` | 与 `_进度/成本台账.csv` 最后一行 `累计CNY` **必须一致**（见 §5） |

> 这一行是**唯一会被反复重写**的地方（它描述"此刻"）；下面三、四节都是**追加**。

### 2.3 `## 一、阶段总表` —— 7 列

原文口径：`| # | 阶段 | 状态 | 产物 | 验收 | 花费 |`

| 列 | 写什么 | 硬要求 |
|---|---|---|
| `#` | 序号，从 1 递增 | 顺序 = **实际执行顺序**（音乐线在前、视频线在后） |
| `阶段` | 阶段名（素材盘点 / 歌词对齐 / 分镜 / 出片 / 字幕 / 合成 / 超分 / 核验 / 封面 …） | 一条线一行，**别把"出片+字幕+合成"塞一行** |
| `状态` | ✅ / 🔄 / ⛔ / ⏸ **四选一** | 见 §3.3；进度写 `🔄 13/17` |
| `产物` | `[名字](相对路径)` **可点击** | 见 §3.1——**这是本表的灵魂** |
| `验收` | **真实结论 / 数字**，不是"已完成" | 如 `17 段`、`7/7`、`21/24 句 ≤0.32s`、`−14.1 LUFS`；无验收写 `—` |
| `花费` | `¥0` 或 `¥<NN.NN>` | 免费阶段**必须写 `¥0`**，不要留空（留空看起来像"忘了"） |

**覆盖率要求**（开发计划 §11 总验收标准）：

> 「**进度文档**：`_进度\进度.md` 覆盖全阶段，产物路径可点击」

**音乐线 + 视频线都要有行**——只写视频线，用户会以为音乐是别人做的。

### 2.4 `## 二、操作日志（新→旧）` —— 每条四要素

原文口径：「每条写「命令 / 产物 / 花费 / 证据」」。

```markdown
### 2026-09-27 17:00 ｜ 重出段 13（修正末帧衔接）
- 命令：`node scripts/82_pv_clips.mjs --only 13 --max-cost 25`
- 产物：`10_h3video/pv/clips/13_inter_b.mp4`（1344×768 / 10.13s）
- 花费：¥6.50（累计 ¥109.50）
- 证据：台账 `_进度/成本台账.csv` 第 5 行；`verify/report.md` 接点 12→13 SSIM 0.885
```

| 要素 | 要求 |
|---|---|
| **命令** | **可复制重跑**的原文（含 `--only` / `--max-cost` 等开关）。人工步骤写"人工 + 工具名" |
| **产物** | 相对路径 + 关键规格（分辨率/时长/体积）。**用行内代码**，路径可点则用链接 |
| **花费** | 本笔金额 + **括号里的累计**。免费写 `¥0（本地）` |
| **证据** | 指到**可复核的地方**：台账行、`verify/report.md` 的哪一项、ffprobe 的哪个数、SSIM 值 |

**顺序：新 → 旧**（最新在最上面）。理由：用户打开文件第一眼看到的是最近发生了什么。

**分节粒度**：一次"批操作"一节（一次批量出片 = 一节；单独重出某段 = 单独一节）。不要每次工具调用都写一节——日志会变成流水账。

### 2.5 `## 三、待用户决定`

只放**真的等用户点头**的事，用复选框。**该放**：需要用户审美/预算判断的（封面选哪版、要不要上 2K）、
有**选项 + 代价**的（"2K 真出 × 165.86s ≈ ¥49.76"）、用户明确提过还没回话的。
**不该放**：自己能查清楚的、纯抱怨、已经决定完的。

```markdown
- [ ] 封面定稿（A/B/C/D 四版）
- [ ] 是否要 2K 真出片（`h3-2k-regen` ¥0.30/s，**未实测**）
- [ ] LRC 三句超阈值（0.810s / 0.780s / 0.570s）是否回头修
```

**条目一旦被决定，就从本节移除**，并在操作日志补一条——本节是"活的待办"，不是历史。

### 2.6 `## 四、变更历史`

记录**产物被替换**的迭代（配合 `SKILL.md` §3 铁律 2「迭代替换」）：

```markdown
- 2026-09-27 15:00 v1 → v2：段 01/02/03 改连续三镜（旧版归档 `10_h3video/pv/history/20260927-233420/`）
```

只记**已归档**的变化（`history/<时间戳>/` 真的存在才写），写清**改了什么 / 为什么 / 旧版在哪**。
归档目录必须有自己的 `README.md` 说明改因（本歌已有 `10_h3video/pv/history/20260927-233420/README.md`）。

## 3. 四条硬规则

> 以下四条出自开发计划 §5.5「规则」，**原文照抄**，逐条解释。

### 3.1 「产物一律写成**可点击的相对路径**（用户要能直接点开）。」

- 写 `[shotlist.csv](../10_h3video/pv/plan/shotlist.csv)`，**不写** `E:\Videos\未来再见翻填\10_h3video\pv\plan\shotlist.csv`。
- 相对路径的**基准是 `进度.md` 自己所在的目录**（即 `_进度/`），所以视频线产物是 `../10_h3video/pv/...`。
- 路径要**正确**：写错一个字，用户点开是 404，这份文档就失去意义。写完通读一遍。
- 目录级产物也给链接（`[clips/](../10_h3video/pv/clips/)`），用户点进去能看全部 17 段。
- 分隔符用 `/`（Markdown 链接里反斜杠会失效）。

> **例外**：操作日志里的「命令」「证据」用行内代码（反引号）更好读——那是给人复制/对照的，不是给人点的。

### 3.2 「花费逐笔记，含累计。」

- **逐笔**：每一笔真实支出都要单独一条，不许合并成"出片共花 ¥109.50"。
- **含累计**：每条末尾写 `（累计 ¥NN.NN）`，让用户能顺着加。
- 免费动作也写 `¥0`——它证明"这一步是本地算力，没花钱"，是**成本纪律的证据**。
- 数字来源：`_进度/成本台账.csv`（`时间,阶段,项目,金额CNY,累计CNY,备注`）。**不要四舍五入抹零**：¥5.50 就写 ¥5.50。

### 3.3 「状态**只用** ✅ / 🔄 / ⛔ / ⏸ 四种。」

| 符号 | 含义 | 用在哪 |
|---|---|---|
| ✅ | 完成且**已验收** | 阶段收口 |
| 🔄 | 进行中（**带分母**：`🔄 13/17`） | 正在跑的阶段 |
| ⛔ | **缺料 / 卡住**（不是"没做"） | 素材没到位、外部服务没开（如 ACE Studio 未运行） |
| ⏸ | 还没开始 | 排队中、等前面完成 |

**禁止**：`✔` `√` `[x]` `done` `完成` `进行中` `50%` `🚧` `⚠️` 等任何其它符号。
理由：这四个符号是**工作台解析进度.md 时的约定**（开发计划 §7.3「清单」Tab 读的就是它），换成别的符号 UI 就渲染不出状态徽章。

> `⛔` 与 `⏸` 最容易混：`⏸` = 计划里有、还没轮到；`⛔` = 轮到它了但**做不了**（缺输入/缺环境）。**卡点必须用 ⛔**。

### 3.4 「**追加**，不重写历史。」

- 操作日志**只往下加**，新条目插到**最上面**——旧条目一个都不删。
- 改产物时：**先**在 §四 写归档记录、把旧产物移进 `history/<时间戳>/`，**再**动新产物。
- 允许改的只有三处：头部引用行（"此刻"快照）、阶段总表（状态列会推进）、待决策（条目会消耗掉）。
- **删掉历史 = 丢失证据**。用户要回溯"上次为什么重出段 13"时，删掉的那条就是答案。

## 4. 什么时候写

| 时机 | 写什么 |
|---|---|
| **每批操作结束** | 操作日志加一条（命令/产物/花费/证据）+ 更新头部与阶段总表 |
| **出片：每段成功或失败都记** | 成功记 ¥ 与时长；**失败也要记**（`成本台账.csv` 第 3 行就记了段 8 两次提交失败，¥0）——失败率是判断"要不要换 prompt 写法"的依据 |
| **改/重出产物之前** | **先归档**（移到 `history/<时间戳>/` + 写 README），**再**改；改完在 §四 记一行 |
| 花钱前后 | 先报预估拿授权（`SKILL.md` §0 第 4 条），花完立刻记账 |
| 阶段收口 | 阶段总表状态改 ✅，`验收` 列填真实数字 |
| 卡住 / 缺料 | 状态改 ⛔，并在 §三 写清"卡在哪、需要用户做什么" |
| 新会话开工 | 先读、再判断断点；**如果读完发现文档过期，先把文档补正再干活** |

**不写的时机**：单次只读查询、纯探索（`--plan`、`ffprobe` 看一眼）——这些不进日志，否则日志被噪音淹没。

## 5. 与 `成本台账.csv` 的关系

### 5.1 分工

| 文件 | 给谁读 | 格式 | 谁写 |
|---|---|---|---|
| `_进度/进度.md` | **人**（用户） | Markdown，带解释 | Agent 每批次**追加** |
| `_进度/成本台账.csv` | **脚本 + 工作台** | `时间,阶段,项目,金额CNY,累计CNY,备注` | 出片脚本**自动追加** |

> 出处：开发计划 §8.2「状态文件」——`进度.md` 性质是"人读进度 + 产物索引"，`成本台账.csv` 是"逐笔花费"。

### 5.2 两边数字**必须一致**
这是硬要求，不是"最好一致"。三处必须对得上：

1. `进度.md` 头部 `累计花费` = 台账**最后一行**的 `累计CNY`
2. `进度.md` §一 的 `花费` 列逐行相加 = 头部累计（视频线各阶段 + 音乐线 ¥0）
3. `进度.md` §二 的日志金额 = 台账的 `金额CNY` 列（**一一对应**）

```powershell
# 校验：台账最后一行是不是进度.md 头部那个数
Import-Csv _进度\成本台账.csv | Select-Object -Last 1 时间,金额CNY,累计CNY
```

**对不上时**：以**台账**为准（它是脚本写的、不会手误），改 `进度.md`。若台账本身错了（漏记/金额错），**修正台账并在 `备注` 列写清修正原因**，然后同步 `进度.md`。

### 5.3 全链路一致性（第三条链）

台账的累计数**还要**和配置对上，否则工作台的账本与脚本的预算判断会打架：

| 位置 | 字段 | 本歌实测 |
|---|---|---|
| `_进度/成本台账.csv` | 末行 `累计CNY` | **109.50** |
| `_进度/进度.md` | 头部 `累计花费` | **¥109.50** |
| `翻填项目.json` | `budget.spentCny` | **109.5** |
| `翻填项目.json` | `budget.totalCny` | 150（剩余 ¥40.50） |

> `budget.spentCny` 由台账汇总而来，**脚本只读不写**（除非显式 `--sync-budget`）——见配置规范 §6。

## 6. 常见错误（每一条都真的踩过）

| ❌ 错误 | 为什么错 | ✅ 正确写法 |
|---|---|---|
| 写**绝对路径** | 换机/换盘/换歌就失效；且这是"要明确的文件位置"想解决的问题 | `[shotlist.csv](../10_h3video/pv/plan/shotlist.csv)` |
| 把**历史段删掉重写** | 丢失证据，回溯时无据可查；违反"追加不重写" | 新条目加在最上面，旧的保留 |
| 状态用了**别的符号** | 工作台按 ✅/🔄/⛔/⏸ 解析，别的符号渲染不出徽章 | 只用那四个；进行中带分母 |
| 产物路径**不可点**（纯文本/写错） | 用户点不开，文档退化成"要自己去翻" | 相对路径写对，点得开 |
| 只写"**完成了**"不写证据 | 无法复核，等于没写；下个会话无法判断质量 | 写 `7/7`、`SSIM 0.885`、`−14.1 LUFS` 这类可核对的数 |
| `花费` 列**留空** | 看起来像漏记，也破坏 §5.2 的加总校验 | 免费写 `¥0` |
| 金额与台账**不一致** | 用户对账时无所适从；工作台与文档打架 | 以台账为准，两边同步 |
| 失败**不记** | 看不出重试率，"为什么超预算"无从解释 | 失败也记一条，金额 ¥0，备注写原因 |
| 把**创作判断**写进模板 | 违背开发计划 §13「不把创作判断写成硬规则」 | 只记事实与数字，选镜头/定情绪的记录让 agent 判断 |
| 在 `进度.md` 里**重复**记忆库内容 | 双写负担，两边都会过期 | 项目内事实进 `进度.md`，跨会话结论进记忆库 |
| `最后更新` **忘了改** | 文档立刻失去可信度，用户分不清新旧 | 每次追加都顺手改 |
